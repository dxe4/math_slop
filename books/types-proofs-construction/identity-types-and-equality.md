
# Identity types and equality

In type theory, there are two notions of equality: definitional equality, recognised automatically by the type checker, and propositional equality, which requires an explicit proof term. This chapter introduces identity types, explains the distinction, and surveys extensionality principles.

## Definitional equality

Definitional equality is the congruence generated by computation rules. In the simply typed lambda calculus, $(\lambda x.\, t)\,u$ is definitionally equal to $t[u/x]$. The type checker recognizes definitional equality automatically; no explicit proof term is required.

For example, $(\lambda x.\, x)\,u$ and $u$ are definitionally equal. If $\Gamma \vdash t : A$ and $A$ is definitionally equal to $B$, then $\Gamma \vdash t : B$ without additional evidence.

Definitional equality is decidable in many type theories, including Martin-Löf type theory and the Calculus of Inductive Constructions. It is part of the type-checking algorithm, not a proposition to be proved.

## Propositional equality

Propositional equality is an internal type. For a type $A$ and terms $a, b : A$, the identity type $\operatorname{Id}_A(a, b)$, also written $a =_A b$, is the type of proofs that $a$ and $b$ are equal.

The formation rule is:

$$\frac{\Gamma \vdash A \;\text{type} \quad \Gamma \vdash a : A \quad \Gamma \vdash b : A}{\Gamma \vdash a =_A b \;\text{type}}\;(=\text{-form})$$

The introduction rule is reflexivity:

$$\frac{\Gamma \vdash a : A}{\Gamma \vdash \operatorname{refl}_a : a =_A a}\;(=\text{-intro})$$

The elimination rule, called $J$, expresses that any property respecting reflexivity extends across all equality proofs:

$$\frac{\Gamma \vdash c : a =_A b \quad \Gamma, x : A, y : A, p : x =_A y \vdash C(x, y, p) \;\text{type} \quad \Gamma, z : A \vdash d : C(z, z, \operatorname{refl}_z)}{\Gamma \vdash J(c, d) : C(a, b, c)}\;(=\text{-elim})$$

The computation rule says $J(\operatorname{refl}_a, d)$ reduces to $d[a/z]$.

## The distinction in practice

Conflating definitional and propositional equality is a common source of errors in proof engineering. Definitional equality is automatic; propositional equality requires an explicit proof. If two terms are not definitionally equal, the type checker rejects them, and an explicit propositional equality must be constructed and transported.

For example, in a dependent type $\operatorname{Vec}(A, m + n)$, if a term has type $\operatorname{Vec}(A, n + m)$, the type checker does not automatically recognise $m + n = n + m$ as definitional equality (in most theories). A propositional proof of commutativity must be applied to transport the term from one type to the other.

## Extensionality principles

**Function extensionality.** Pointwise equal functions are equal:

$$\frac{\Gamma \vdash f : \Pi x : A.\, B(x) \quad \Gamma \vdash g : \Pi x : A.\, B(x) \quad \Gamma \vdash p : \Pi x : A.\, f(x) =_{B(x)} g(x)}{\Gamma \vdash \operatorname{funext}(p) : f = g}$$

Function extensionality is not provable from $J$ alone in many type theories; it is an axiom or a principle added to the system.

**Propositional extensionality.** Logically equivalent propositions are equal:

$$\frac{\Gamma \vdash P \;\text{prop} \quad \Gamma \vdash Q \;\text{prop} \quad \Gamma \vdash p : P \to Q \quad \Gamma \vdash q : Q \to P}{\Gamma \vdash \operatorname{propext}(p, q) : P = Q}$$

**Univalence.** In homotopy type theory, the univalence axiom states that equivalences between types correspond to equalities in a universe. It is a powerful extensionality principle with significant consequences for mathematics formalized in type theory.

These principles are not automatic theorems of every dependent type theory. They are axioms or principles in specified systems, and their computational interpretations vary.

## Worked example: transporting along equality

Suppose $v : \operatorname{Vec}(\mathbb{N}, 2 + 3)$ and we need $v' : \operatorname{Vec}(\mathbb{N}, 3 + 2)$. Since $2 + 3 = 5$ and $3 + 2 = 5$ are definitionally equal in many systems (by recursive definition of addition), no transport is needed.

But if $m$ and $n$ are variables, $m + n$ and $n + m$ are not definitionally equal. We need a proof $p : m + n =_{\mathbb{N}} n + m$ and apply transport:

$$\operatorname{transport}^{\operatorname{Vec}(\mathbb{N}, -)}(p, v) : \operatorname{Vec}(\mathbb{N}, n + m).$$

The transport function is defined by $J$. For $B:A\to\operatorname{Type}$, use the motive

$$C(x,y,p)\equiv B(x)\to B(y)$$

and the reflexivity case $d\equiv\lambda z.\,\lambda u.\,u$. Then

$$\operatorname{transport}^{B}(p,t)\equiv J_C(d,a,b,p)(t)$$

for $p:a=_A b$ and $t:B(a)$. The computation rule gives $\operatorname{transport}^{B}(\operatorname{refl}_a,t)\equiv t$.

## Common errors

**Error: expecting definitional equality where only propositional equality holds.** A proof may establish $a = b$ propositionally, but the type checker will not accept $a$ where $b$ is expected. Explicit transport is required.

**Error: applying function extensionality without checking system support.** Some proof assistants do not have function extensionality as a definitional rule. Using an opaque axiom supplies no new computation rule; other foundations can give extensionality a computational interpretation.

**Error: confusing $=$ in type theory with equality in set theory.** In first-order set theory, equality is a primitive logical relation constrained by the equality rules and by the axiom of extensionality; it is not defined as membership. In intensional type theory, identity types are inductively generated by reflexivity (in the standard formulation), with $J$ as eliminator.

## Worked example: symmetry and composition from identity elimination

For $p:a=_A b$, define its inverse by $J$ with motive $C(x,y,p)=(y=_A x)$ and reflexive case $\operatorname{refl}_z$. This gives $p^{-1}:b=_A a$, with $(\operatorname{refl}_a)^{-1}\equiv\operatorname{refl}_a$. The construction does not inspect a secret list of alternative equality constructors. It uses the eliminator that justifies extending a definition from reflexivity to arbitrary endpoints and paths.

For $p:a=b$ and $q:b=c$, define composition $p\cdot q:a=c$ by eliminating $q$, keeping $a$ and $p$ as parameters. A convenient motive is
$$C(x,y,q)=(a=x)\to(a=y),$$
whose reflexive case is the identity function. Applying the resulting map to $p$ gives composition. Its chosen computation equation is $p\cdot\operatorname{refl}_b\equiv p$. The equation $\operatorname{refl}_a\cdot p=p$ is also provable, but need not be definitional for this choice of eliminator. Identity induction on $p$ proves it, since the reflexive instance computes to reflexivity.

The orientation is worth checking. A proof $a=b$ followed by $b=c$ yields $a=c$. If the second supplied proof instead has type $c=b$, first invert it. The same discipline prevents transporting a term in the wrong direction when its dependent type changes. Printed equality symbols do not remove the source and target information attached to their proof terms.

## Worked example: applying a function to a path

Let $f:A\to B$ and $p:a=_A b$. Use $J$ with motive
$$C(x,y,p)=(f(x)=_B f(y))$$
and reflexive case $\operatorname{refl}_{f(z)}$. The result is $\operatorname{ap}_f(p):f(a)=_B f(b)$, and the reflexive computation is $\operatorname{ap}_f(\operatorname{refl}_a)\equiv\operatorname{refl}_{f(a)}$.

This is congruence: a fixed function maps an equality between inputs to an equality between outputs. It is different from function extensionality, which takes an entire family of equalities $f(x)=g(x)$ and asks for an equality between the functions themselves. Congruence follows from $J$ by the displayed construction. Function extensionality is an additional principle in the basic intensional setting described here. Confusing the two would hide an actual change of foundation behind the everyday phrase equal functions.

For example, a proof $m+0=m$ yields $S(m+0)=Sm$ by applying successor. This is exactly the operation used in the inductive addition proof. The arithmetic proposition and its path are explicit. A kernel accepting the resulting proof does not thereby identify all expressions denoting equal natural numbers through its built-in conversion relation.

## A transport calculation with hypotheses visible

For a family $B:A\to\mathrm{Type}$ and $p:a=b$, transport is a function $B(a)\to B(b)$. If $B$ is constant at a type $D$, transport along reflexivity computes to the identity on $D$. Transport along an arbitrary path in a constant family is propositionally the identity, proved by eliminating that path; it need not be the same printed or definitionally reduced expression before elimination.

**Proposition 9.1 (Transport respects a reflexive path).** For every $a:A$ and $u:B(a)$, $\operatorname{transport}^{B}(\operatorname{refl}_a,u)\equiv u$ under the stated computation rule.

*Proof.* Its definition uses the reflexive branch $\lambda u.u$ of $J$. Substituting a reflexive path triggers the computation equation and returns that branch applied to $u$, which beta-reduces to $u$. ∎

A related propositional law is that transport along $p$ and then $p^{-1}$ returns the original element. Identity induction on $p$ reduces the statement to transport twice along reflexivity; both transports compute to the identity, and reflexivity proves the remaining equality. The proof must quantify over the element in its correct endpoint fibre. Moving an element between fibres without recording the path is precisely the operation this law is meant to justify.

## Why path induction does not silently prove uniqueness of identity proofs

The rule $J$ permits an appropriately dependent definition with a branch at reflexivity. It does not say that every equality proof at fixed endpoints is definitionally the reflexive constructor. In the eliminator, endpoints and the path are generalised together. A proposed argument fixing an endpoint too early may ask for a motive or branch that does not have the type required by $J$.

For example, the principle that any two proofs $p,q:a=b$ are themselves equal is called uniqueness of identity proofs, or UIP. This is an extra property of a type or a foundation, not an immediate consequence of the single constructor printed in the introduction rule. A proof of nonderivability in an entire theory requires a metatheoretic model, as with the earlier function-extensionality discussion. Inspecting constructor syntax is not such a model.

Some types can have uniqueness properties for additional reasons. A discrete datatype with decidable equality has further structure that can be used in the relevant theorem. The homotopy chapter instead studies types whose identity structure carries higher information. The present chapter need not decide those later examples to insist that the logical principles remain separate.

## Equality in a concrete development

When a term fails to fit an expected dependent type, first write the two indices and their computational definitions. If they reduce to the same expression, conversion may suffice. If a propositional equality relates them, write its direction and transport in the family containing the term. If only a pointwise equivalence or logical implication is known, an equality of types or functions needs another explicit principle.

This sequence distinguishes a missing arithmetic proof from a missing extensionality axiom. It also avoids applying transport as an unexplained cast. The equality is part of the term's derivation and should remain available to inspect. In large proof developments, notation and coercions may hide it at the surface, but the foundational justification is still identity elimination or an explicitly stronger rule.

## Congruence laws proved by path induction

For the identity function on $A$, there is a propositional law $\operatorname{ap}_{\mathrm{id}}(p)=p$. Eliminate the path with both endpoints generalised. At reflexivity, the congruence construction computes to reflexivity, so the required higher identity is reflexive. The eliminator extends that branch to all paths. Unless further conversion rules are supplied, this proof does not turn the original open expression with a variable path into a new unconditional computation rule.

For functions $f:A\to B$ and $g:B\to C$, the corresponding composition law is that applying congruence for $g\circ f$ agrees propositionally with first applying congruence for $f$ and then for $g$. Again, eliminate the input path. Both constructions reduce to reflexivity at the same composite value in the reflexive case, so reflexivity supplies the branch. These small theorems show that equality elimination coheres with familiar function operations.

The laws are about equalities between **proof terms** whose endpoints already agree. They illustrate why identity types can be iterated: paths between data have their own identity types. No new constructor is needed to state those higher identities. Equally, the presence of an identity type between two proof terms does not by itself mean it is inhabited. The displayed induction arguments supply the evidence in these particular cases.

Keeping definitional and propositional claims distinct pays off here. A simplifier may use these proved laws as rewrite lemmas, while the kernel's primitive reduction relation still has only its chosen computation equations. Successful rewriting by a library theorem is not evidence that the theorem was definitional all along. It is a small proof transformation whose mathematical warrant should remain identifiable.

## Composition of transport and dependent congruence

Transport has a composition law with a fully typed proof. Fix a family $B:A\to\mathrm{Type}$, paths $p:a=b$ and $q:b=c$, and an element $u:B(a)$. Transporting $u$ along the composite $p\cdot q$ and transporting first along $p$ and then along $q$ both produce elements of the same final fibre $B(c)$. The law asserts a propositional equality between those elements; it does not identify the two open expressions by an additional conversion rule.

To prove it, keep the first path and the element as parameters and eliminate the second path with its final endpoint generalised. The motive at an endpoint $c$ and path $q:b=c$ is the identity type in $B(c)$ between the two proposed results. At the reflexive path at $b$, our chosen composition rule makes the composite with reflexivity compute to $p$. Transport along the second reflexive path also computes to the identity on $B(b)$. Both sides therefore reduce to transport along $p$ applied to $u$, and reflexivity supplies the branch. Identity elimination extends that branch to every final endpoint and second path. Each term stays in its declared fibre throughout the argument.

There is also a dependent version of applying a function to a path. Suppose $f:\Pi x:A.B(x)$. The values $f(a)$ and $f(b)$ initially inhabit different fibres, so an ordinary identity between them would be ill typed. First transport $f(a)$ along $p:a=b$; the result lies in $B(b)$ and can be compared with $f(b)$. Identity induction on $p$, generalising both endpoints as required, constructs that comparison. In the reflexive case transport computes away and both terms are the same value, so reflexivity again supplies the branch.

These arguments explain a common proof-engineering distinction. Congruence for a nondependent function compares output values directly. Dependent congruence must also account for the changing output type. Neither construction needs function extensionality, because each concerns a fixed function and a given input path. Neither says that all paths between the endpoints are equal. The proofs provide these particular higher equalities through their displayed motives and computation rules, retaining the distinction between path laws and primitive reduction.

<details><summary>Hint 2</summary>

## Chapter summary

Definitional equality is automatic computation recognised by the checker. Propositional equality is an inhabited type $a =_A b$ with reflexivity as constructor and $J$ as eliminator. Extensionality principles (function extensionality, propositional extensionality, univalence) are not automatic theorems; they are axioms in specified systems. Conflating the two notions of equality is a frequent source of proof engineering errors.
