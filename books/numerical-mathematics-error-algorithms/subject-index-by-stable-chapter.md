## Problem-to-evidence index

**A formula loses digits near a limiting value.** Start with `finite-precision-conditioning`. Report an exact reformulation when available, condition analysis of the mathematical function, exceptional-value behavior, and comparison against a higher-accuracy or enclosure reference.

**Parallel summation changes between runs.** Start with `finite-precision-conditioning`; add `verified-interval-computation` for directed-rounding interval reductions. Report the reduction tree, formats, threads, exceptional-value policy, reference sum, and whether the target is small error, deterministic rounding, or bitwise agreement.

**A scalar equation may have several roots.** Use `nonlinear-equations`. Report the search domain, continuity and bracket evidence, monotonicity or derivative information for uniqueness, termination interval, and treatment of even-multiplicity roots.

**A nonlinear system solver reports convergence.** Use `nonlinear-systems-globalization`. Report variable and residual scaling, Jacobian source and check, step acceptance history, final residual, conditioning evidence, and whether the desired root is uniquely identified.

**Scattered or nodal data need an approximation.** Use `interpolation-splines-least-squares`, then `orthogonal-minimax-approximation` if weights or worst-case error matter. Report nodes, basis, objective norm, rank/conditioning, held-out or exact comparison, and evaluation method.

**A global expansion shows rapid coefficient decay.** Use `spectral-approximation`. Report domain map, node and transform conventions, aliasing checks, coefficient tail, error at independent points, and regularity assumptions behind any convergence-rate claim.

**A derivative or integral needs trustworthy digits.** Begin with `differentiation-quadrature`; add `difficult-integrals-high-dimension` for singularity, oscillation, or dimension. Report smoothness or transformation, rule and exactness, step/sample history, error proxy, arithmetic floor, and independent benchmark.

**A linear solve has a small residual but suspicious components.** Use `matrix-computation-applications:floating-point-and-factorization`, `matrix-computation-applications:sparse-and-iterative-methods`. Report componentwise and normwise scaling, factorization or iteration, preconditioner, backward error, condition estimate, and a higher-precision or exact residual when warranted.

**Eigenvectors change dramatically under tiny perturbations.** Use `matrix-computation-applications:qr-least-squares-svd`, `matrix-computation-applications:eigenvalue-computations`. Report normality or nonnormality, eigenpair residuals, separation, subspace angles, singular values, and the perturbation model.

**A randomized matrix approximation is fast but variable.** Use `matrix-computation-applications:randomized-numerical-linear-algebra`, `matrix-computation-applications:mixed-precision-verified-computing`. Report distribution, seed/generator, oversampling, power steps, arithmetic formats, failure budget, and deterministic residual or holdout check.

**An ODE solution changes when the step shrinks.** Use `initial-value-methods`; use `multistep-stiff-dae-methods` for stiff decay, history, or constraints. Report equation/data, method, stability regime, accepted/rejected steps, error estimates, event rules, invariants, and a refinement/reference comparison.

**A field solver appears converged.** Use `boundary-value-pde-methods`, `finite-volume-element-methods`, and `nonlinear-adaptive-field-methods` as appropriate. Report domain, boundary conditions, weak/flux form, mesh family, quadrature, algebraic/nonlinear tolerances, balance, residual or estimator, and output refinement.

**A numerical result must support an audit or publication.** Use `numerical-capstone-software-audit` and `verified-interval-computation`. Report the full artifact schema, adverse fixtures, independent checks, rerun instructions, accessibility alternative, supported claim, and unresolved uncertainty.
