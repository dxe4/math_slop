Noisy clues and short binary descriptions

This route links two uses of probability. A noisy clue changes uncertainty about a hidden bit, while a prefix tree assigns codeword lengths to symbols with known weights. The goal is to calculate both carefully and explain why one is an information measure and the other is an actual coding cost. Seven articles provide the main teaching; this wrapper adds a common data set and mixed tasks. Allow about 390 minutes: 176 minutes for the articles, 115 minutes for rebuilding tables and trees, and 99 minutes for the mixed practice and capstone. It covers a finite source and a one-use toy channel, not a general communications design.

Entry recap. Probabilities in a finite table sum to one. A conditional probability divides a joint cell by the relevant positive row or column total. Entropy H is average −log₂ probability, measured in bits; zero-probability terms contribute zero by continuity. A binary tree's leaf depth is an integer codeword length. Every calculation below uses stipulated probabilities, so a handful of observed outcomes would not automatically justify the model.

Two modules with a common checkpoint

Refresh core ideas

  1. How surprising is a symbol? Check additivity only for independent events. This gives a unit for one observation and a warning about applying the product rule without a joint model.
  2. Average surprise in a mystery bag Move from an observed symbol to uncertainty before observation. Recalculate the binary maximum and explain why a rare event can be individually surprising inside a low-entropy source.
  3. Two clues can repeat information Draw both the copying and independent tables. The chain rule is the bridge to asking how much uncertainty remains after a clue, rather than just adding two separate entropies.

At this checkpoint, invent a two-by-two joint table and verify each marginal by summing a row or column. State whether H(X,Y)=H(X)+H(Y) is licensed. If the table is neither independent nor deterministic, calculate H(Y|X) directly from each positive row before proceeding.

Work across examples

  1. How much does one clue reveal? Subtract remaining uncertainty from initial entropy. Explain why the result is symmetric despite the phrase “clue about a hidden value,” and why zero covariance need not imply zero information.
  2. Make a code no symbol can confuse Turn symbol weights into an actual binary tree. Check both the prefix property and the weighted length; an entropy figure is not itself a complete code.
  3. Why common symbols get short codes Use repeated lowest-weight merges to optimize a finite prefix tree. Name the known-weight, binary, per-symbol and average-length assumptions before claiming optimality.
  4. A message through a fickle switch Return to the joint table for a fair input and a specified flip chance. Distinguish mismatch probability, remaining entropy and mutual information, which have different units or interpretations.

The coding pair and the channel lesson answer distinct questions. A channel can introduce uncertainty about an input after transmission; a source code exploits known frequency differences before transmission. Combining them into a real system requires design choices beyond this route. Here the shared discipline is to write the probability law and the objective before selecting a formula.

Mixed practice: one source, two operations

Take source weights A=1/2, B=1/4, C=D=1/8. Its entropy is 7/4 bits. A Huffman merge joins C and D to 1/4, then that node with B to 1/2, then with A. Codewords A→0, B→10, C→110, D→111 have expected length 7/4 bits. Now imagine A is represented by input bit 0 and B by bit 1 in a separate binary switch experiment; do not assume the four-symbol code itself defines a one-bit channel. If the binary switch input is fair and flips with probability 1/4, its joint table is (3/8,1/8;1/8,3/8). Its mismatch chance is 1/4 and its mutual information is 1−h₂(1/4)≈0.189 bit per use. The two bit quantities refer to different random variables, so comparing them as if they were competing compression rates would be meaningless.

Capstone: compare clues and code trees

Let the hidden input bit have P(X=0)=3/4 and P(X=1)=1/4, and send it through a switch that flips with probability 1/4. Build the joint X,Y table and find H(X|Y) and I(X;Y), taking care that the output is no longer fair. Separately use source S with probabilities A=2/5, B=3/10, C=1/5, D=1/10. Run Huffman merges, assign one valid code, and compare its average length with a fixed two-bit code. Verify prefix freedom and compute H(S) to show the coding gap. Explain why all results depend on the stated weights and switch law.

Model solution

The channel cells are P(0,0)=9/16, P(0,1)=3/16, P(1,0)=1/16, and P(1,1)=3/16. They total one; P(Y=0)=10/16=5/8 and P(Y=1)=6/16=3/8. Given Y=0, the input is zero with probability 9/10. Given Y=1, the input is zero with probability 1/2. Hence H(X|Y)=(5/8)h₂(1/10)+(3/8)·1≈0.668 bit. H(X)=h₂(1/4)≈0.811 bit, so I(X;Y)≈0.143 bit. Using h₂(1/4) for H(X|Y) would incorrectly treat the nonfair input as fair.

For S, merge D and C to weight 3/10, merge that node with B to weight 3/5, then join with A. One code is A→0, B→10, C→110, D→111. Its words are prefix-free and Kraft sum is 1. Expected length is (2/5)1+(3/10)2+(1/5)3+(1/10)3=19/10=1.9 bits per symbol. A fixed two-bit code is also prefix-free and costs 2 bits, so Huffman saves 0.1 bit per symbol under these weights. H(S)=−(2/5)log₂(2/5)−(3/10)log₂(3/10)−(1/5)log₂(1/5)−(1/10)log₂(1/10)≈1.846 bits. Thus the Huffman mean is about 0.054 bit above entropy. Different source weights may change the optimal tree; a different input law changes the channel posterior. The source code and bit switch remain separate models.

Self-review rubric. Check four normalized joint cells, the correct positive conditioning denominator, entropy in bits, a valid prefix test, source-weighted rather than unweighted code length, and a stated scope for every comparison. A correct number with no declared source or channel law is incomplete.
