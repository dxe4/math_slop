Algorithms with reasons

This route is for readers who know induction and logarithms but want a compact return to rigorous algorithm analysis. It joins three styles of argument: an invariant that makes a search correct, a recurrence that prices recursive work, and a state invariant that proves a string recognizer. You will produce a search comparison with a real proof. Allow roughly eleven hours for six article readings, proof revisions and the capstone; a quick skim of the links will not deliver that outcome.

Entry recap. For a sorted list, indices increase with values. A half-open interval [lo,hi) contains lo but excludes hi. An induction proof starts at a base case and derives a larger case from a smaller one. A logarithm log₂n counts how many halvings take a power of two to one. Big O says there are constants C and n₀ bounding one nonnegative function by C times another for every n≥n₀. Each article repairs its own notation; use this paragraph as a reminder, not as a substitute for the arguments.

The scope is exact comparison and operation models on finite inputs. We will not use wall-clock timings to prove asymptotics, and we will not claim a general sorting lower bound. Your stopping point is a justified choice between two search strategies on a sorted archive, together with an exact recurrence solution for a related preprocessing task.

Three modules, each with a bridge

  1. Search and cost. Read Why halving a search works and Big O is an eventual bound. The first article's invariant explains why a half can be discarded; the second turns its comparison count into an eventual bound with constants. Rewrite the first-occurrence proof in your own words before estimating anything. Ask whether your target may be absent or repeated, because those cases change the postcondition.
  2. Reuse work. Read A recursive algorithm's bill and Remembering subproblems. A divide-and-conquer recursion tree charges each level; a dynamic-programming table saves repeated subproblem answers. The bridge is the shape of the dependency graph: two branches are not automatically duplicate work, and shared subproblems are not automatically cheap unless there are few distinct states. Re-solve T(8) by a tree and by substitution to see the agreement.
  3. Finite states. Read A machine with finite memory and Patterns and machines. Here an invariant describes the meaning of a state after each prefix rather than the range of remaining search candidates. The same base-and-step discipline proves both. Trace 0101 in each machine and state why parity and ending-in-01 are separate properties.

These modules are not a chronological history of computer science. They are three reusable proof moves. After each, write down the contract, the invariant, the operation counted, and one input violating a needed precondition. This short ledger makes the capstone's assumptions visible.

Worked mixed practice: an archive choice

Suppose a sorted archive contains 64 records and you search once for a target. A linear scan from the start may inspect all 64 records, so its worst-case comparison count is 64. The lower-bound binary search in the lesson inspects at most floor(log₂64)+1=7 middle entries, plus one final equality check, so at most eight comparisons in this accounting. The guarantee applies even if the target is absent. For a repeated target, stopping at the first equal midpoint would not necessarily return its first position; the boundary version does.

Now suppose preprocessing creates a balanced summary tree with cost T(n)=2T(n/2)+n and T(1)=1 for n a power of two. For 64 records, the recurrence solution gives T(64)=64(6+1)=448 model operations. If you build that summary solely to perform one binary search on an already sorted array, the 448 extra operations make little sense. If the summary answers many other queries, its one-time cost might be useful, but you must specify those queries to judge it. The arithmetic is exact in the model; no milliseconds were measured.

For a batch of 20 independent searches on the same sorted archive, plain repeated binary search uses at most 20·8=160 comparisons under our bound. A linear scan for every query may take 20·64=1,280 comparisons. These are upper bounds; an early match can make a particular linear search shorter. A failed target at the end makes the worst case relevant. Big O alone would hide the batch size and the preprocessing bill, which are important for this concrete decision.

Compare two search plans and prove the bounds

An archive has n=2k sorted records with possible duplicate keys. A query asks for the first index holding a target, or ABSENT. Plan A scans indices in order until the first match or the end. Plan B uses the lower-bound binary search from its lesson and one guarded final equality check. For n=128 and q=50 independent queries, compute valid worst-case comparison bounds for both plans. State an invariant and termination measure for each. Prove Plan B's first-occurrence result. Finally analyze the optional preprocessing recurrence S(1)=1, S(n)=2S(n/2)+n and decide whether building it solely for these searches is justified by the given operation counts.

Hint

For Plan B, keep every value before lo strictly below the target and every value from hi onward at least the target. On each round the candidate interval shrinks. The recurrence has the same cost at every tree level.

Model solution

Plan A makes at most 128 comparisons per query, hence at most 6,400 over 50 queries. Its invariant after index i is that none of the inspected positions 0,…,i−1 equals the target; otherwise it would have returned at the first equal value. Because the list is sorted, once a value exceeds the target a variant could stop even sooner, but the stated scan still has the 128 bound. The remaining-length measure 128−i decreases at every unsuccessful step.

For Plan B, the initial interval has length 128. Each midpoint comparison at least halves the remaining length, with a bound of floor(log₂128)+1=8 midpoint comparisons and one guarded final equality comparison, at most nine per query and 450 across 50 queries. The invariant says every index below lo holds a value less than the target and every index at or beyond hi holds a value at least the target. Sortedness justifies moving lo to mid+1 after a smaller midpoint, or hi to mid otherwise. When lo=hi, it is the first position eligible to equal the target; testing that position yields the first match or ABSENT. The interval length hi−lo is a nonnegative integer that strictly decreases, so the loop stops.

For powers of two, S(n)=n(log₂n+1), proved by the base S(1)=1 and substitution into 2S(n/2)+n. Thus S(128)=128(7+1)=1,024 operations. Adding that solely to Plan B's 450 comparisons gives 1,474 model operations, larger than using the already sorted array directly. These are different kinds of operation unless the model explicitly prices them equally, so a physical time conclusion would need a cost model. Under the problem's unit-operation convention, the extra tree is unjustified for these searches.

Outcome and rubric

OutcomeEvidence
Prove binary searchThe interval invariant, preservation, termination and final boundary argument are explicit.
Use asymptotic boundsThe logarithmic and linear bounds count named operations with a valid threshold.
Analyze recursionThe recurrence has a base case, exact solution and correctly scoped input sizes.

Rubric, twelve points: three for valid numerical bounds, four for the binary-search proof including duplicate and absent cases, two for the scan invariant and termination, two for the recurrence, one for the bounded cost comparison. A timing plot cannot earn proof points. If the inequalities are right but the invariant loses the first-occurrence guarantee, revisit the sortedness step before stopping.

Keep the assumptions beside the answer

You have compared concrete plans, not declared one algorithm universally superior. Binary search wins the named comparison model because the array is already sorted. The recurrence explains an extra preprocessing cost, while the automata module gives a second example of proving behavior by a state meaning. A useful next project is to vary the query count q and preprocessing benefit, then solve the exact break-even inequality under a fully specified cost model.
