Networks and degree counts

A finite simple undirected graph consists of vertices and edges. Each edge joins two different vertices, with at most one edge for each pair. “Undirected” means that AB and BA name the same connection. A drawing shows these relationships; its line lengths need not carry any information.

Worked example. Use vertices A, B, C and D, with edges AB, AC and BC. The degree of a vertex is the number of edges touching it. A, B and C each have degree 2, while D has degree 0 because it is isolated.

2+2+2+0=6=2×3

Every edge contributes one to the degree at each of its two ends. Adding all degrees therefore gives twice the number of edges. An isolated vertex still belongs to the graph and contributes zero to the sum.

Try one. Add the edge CD. What changes?

Worked answer

C's degree rises to 3, and D's rises to 1. A and B stay at 2. The degree sum becomes 8, and there are now four edges, again giving twice the edge count.

Watch the convention. A repeated connection or an edge from a vertex to itself requires a different graph convention. Keep the simple-graph assumptions explicit when translating a real network.

Use graph structure to plan routes and schedules

This route is for a reader who already knows what vertices and edges are and can follow a short proof. It connects five graph techniques without treating them as interchangeable: an Euler trail covers edges once, BFS minimizes edge count from a source, a tree supplies unique paths, and a colouring separates conflicts. Allow about eight hours for the linked lessons, traces, proof practice, and capstone. The concrete output is a route certificate and a schedule bound on one finite model.

Entry recap. A simple undirected graph has a finite vertex set and unordered edge pairs. Degree counts edges touching a vertex. A path has distinct vertices, while a trail has distinct edges and may revisit vertices. Connectedness means each vertex pair can be joined by a path. If proof vocabulary feels rusty, a direct proof starts from stated assumptions and explains each step; a counterexample refutes a universal claim by meeting its assumptions while breaking its conclusion.

Module 1: Routes

  1. Three ways through a network. Make a route log and identify which edge identities repeat.
  2. Can every bridge be crossed once? Use the odd-degree count plus connectedness to decide whether one trail can include every edge.
  3. Shortest routes as a proof problem. Run BFS from a source, record queue layers, and trace a predecessor path.

The first lesson establishes the route language. The second asks for a single trail that covers all edges; its length is predetermined by the number of edges. The third asks for a path with as few edges as possible between chosen endpoints. This bridge matters: an Euler route need not be a shortest trip between its endpoints, and a shortest path usually leaves many edges untouched. For BFS, write the queue after each removal. Merely saying “the nearest vertex is visited first” does not expose the FIFO condition used by the proof.

Module 2: Structure

  1. Why a tree has one fewer edge than vertices. Prove the edge count by deleting a leaf and use unique paths to explain what a new edge changes.
  2. Scheduling by colouring conflicts. Translate incompatible activities to edges, find a proper colouring, and compare it with a lower bound.

The BFS predecessor edges on a connected component form a tree. Each discovered non-source vertex gets exactly one parent at an earlier layer, so following parents cannot cycle and eventually reaches the source. This relates the route module to the tree module. Colouring then asks a different question about the same adjacency information: which vertices may share a slot? Every edge becomes a prohibition on equal colours. The greedy Δ+1 argument offers a safe upper bound; proving an optimal schedule demands a separate lower bound, such as a triangle of pairwise conflicts.

Worked mixed practice: one graph, three questions

Use vertices A,B,C,D and edges AB,BC,CD,DA,AC. First decide whether a route can use every edge exactly once. Then find the BFS distance from A to D. Finally, regard edges as scheduling conflicts and determine the fewest colours. Keep these answers separate even though they use the same edge set.

Hint

Count odd degrees for the first question, inspect A's neighbors for the second, and look for a triangle plus a three-colour construction for the third.

Worked solution

A and C have degree three; B and D have degree two. The graph is connected and has exactly two odd-degree vertices, so an Euler trail exists from A to C; A,B,C,D,A,C is one, using AB,BC,CD,DA,AC. In BFS from A, D is an immediate neighbor, so dist(A,D)=1 and path A,D is shortest by edge count. For colouring, A,B,C form a triangle, forcing at least three colours. Colour A=1, B=2, C=3, D=2: D conflicts with A and C, and all other listed edges also have unlike endpoint colours. Thus the chromatic number is exactly three. The Euler trail has five edges, while the shortest A–D path has one; their objectives differ.

Now remove edge AC as a diagnostic. The remaining four-cycle has all degrees two, so it has an Euler circuit. BFS distance A–D remains one. Colouring now needs only two colours, assigning A,C one colour and B,D the other. A single model edit affects the three questions differently; this is a useful check that the methods answer distinct questions.

Capstone: street inspection and a clash-free schedule

A small street graph has V={P,Q,R,S,T} and edges PQ,QR,RS,SP,PR,RT. An inspector must traverse each street exactly once if possible. Separately, each vertex names a committee meeting; meetings joined by an edge share a person and cannot use the same slot. Give a route or an impossibility proof for inspection. Find a shortest P–T path by edge count and justify the distance. Give a valid slot assignment, a bound on the least number of slots, and a conclusion if the bound is exact.

Model solution

Degrees are P3 (PQ,SP,PR), Q2, R4 (QR,RS,PR,RT), S2, T1. The graph is connected and P,T are its two odd vertices, so an open Euler trail exists. One is P,Q,R,S,P,R,T; its edges are PQ,QR,RS,SP,PR,RT exactly once. P–R–T has two edges, so dist(P,T)≤2. There is no edge PT, so no one-edge P–T path, proving dist(P,T)=2. For scheduling, P,Q,R form a triangle, so at least three slots are required. Assign P=1,Q=2,R=3,S=2,T=1. The six edges each join unlike colours: PQ 1/2, QR 2/3, RS 3/2, SP 2/1, PR 1/3, RT 3/1. Thus three slots suffice and are necessary. The proposed Euler route is a certificate; the degree theorem explains why one should exist, while the explicit edge log checks this particular one.

Stop when the certificate matches the question

This route is complete when you can tell whether a question asks to cover edges, minimize edge count, preserve acyclic connectivity, or avoid conflicts, and can supply a matching certificate or obstruction. All conclusions here concern finite simple unweighted graphs. Weighted travel time and multi-slot meetings require extra model data. For a deeper structural route, the plane-graph formula starts from trees and adds an embedding.
