Where mechanical reasoning reaches a limit

This route asks a precise impossibility question and a separate efficiency question. Could one algorithm correctly decide whether every other program will halt on a given input? Could every decision problem with efficiently checkable YES certificates also be solved efficiently? The first receives a proof of impossibility; the second is the open P versus NP problem. Treating them as the same kind of limit would obscure both. Plan about sixteen hours for six lessons, written proofs, counterexamples and the capstone. This is sustained proof practice within a selected window of theoretical computer science, not a degree-level survey.

Entry recap. A function maps an allowed input to an output. A program in our formal model has a finite description, may take a finite encoded input, and may halt or run forever. Proof by contradiction assumes a claim and derives an impossibility. For asymptotic cost, a polynomial means a fixed-degree expression such as Cnk as input length n grows; the constants cannot depend on n. A decision problem asks YES or NO. These notions are repaired in the linked articles, but the capstone expects you to state them without hand-waving.

The main stopping point is a public explanation of the halting theorem that survives a skeptical reader's questions: Which program is given to the checker? Why can it inspect its own description? What happens under each possible answer? Alongside it, you must correctly define P and NP and say why the halting theorem does not resolve their equality. This course does not prove the full Church–Turing thesis, NP-completeness or any separation between P and NP.

Follow the three proof modules

  1. Formal preparation. Read What counts as an algorithm?, Big O is an eventual bound, and A machine with finite memory. The scan proof separates correctness from termination. Big O separates a quantified eventual bound from a table of timings. The automaton proof shows what an invariant can establish for all finite input words. Bridge them by writing a contract for each machine and identifying which universal claim its proof actually covers. A DFA always finishes reading a finite input, but that property does not extend to every general program.
  2. Machines and limits. Read Patterns and machines, then The program no checker can always judge. The first constructs a tiny machine that always halts and proves a precise accepted language. The second assumes a universal halting decider and designs a new program that contradicts it on self-input. The bridge is expressive power: finite automata are deliberately restricted, while the halting theorem requires a model capable of encoding and running arbitrary programs. Do not use the automaton's finite transition table as if it were already a universal machine.
  3. Efficient checking. Read Checking and finding are different questions. Now the question is how many steps a decider or verifier uses as a function of encoded input length. The inclusion P⊆NP has a short proof from definitions. The equality question remains open. Bridge back to halting by stating the different quantifiers: “no decider at all for every program-input pair” is a computability result; “is there a polynomial-time solver for every efficiently verifiable decision language?” is an efficiency problem within decidable languages.

For each module, make a one-page proof ledger. Put assumptions on the left, the exact conclusion on the right, and a counterexample to a tempting stronger claim below. This habit matters here because a correct proof of a narrow claim is easily misreported as a solution to a much broader question. Keep finite traces as checks of your notation, never as substitutes for a universal argument.

Worked mixed practice: three different guarantees

Consider the two-state parity DFA over binary strings from the finite-automata lesson, which accepts exactly the strings with an odd number of 1s. On input 101 it makes exactly three transitions and accepts because there are two 1s? Check the trace: E→O after 1, O→O after 0, O→E after 1, so it rejects. The stated count of 1s is two, and that is even. This deliberate near-miss shows why a trace must include every state rather than relying on a hasty verbal impression. The DFA is guaranteed to halt after the third symbol because its transition function is total and input length is finite.

Now ask whether an arbitrary encoded program P halts on input 101. A finite trace of P for three or three million steps may show a halt, but if it has not halted, the trace cannot prove it never will. A universal checker H that always answers correctly is ruled out by the diagonal construction in the halting lesson. This is a stronger statement than “our current tools are slow”; it is an impossibility within a universal program model.

Finally consider the decision problem “does a binary string contain a 1?” A left-to-right scan decides it in at most n inspections for length n, so it belongs to P. It also belongs to NP: a verifier can ignore a certificate and run the same scan, using the empty string as certificate. The existence of this easy problem in both classes says nothing about whether P=NP. The halting theorem does not exclude this particular decision problem, because its bounded scan always finishes. These three examples occupy different levels: a finite-state trace, an undecidable all-program question, and a polynomial-time decidable language.

There is a useful failed argument to diagnose. “The parity DFA always halts, so every program has a decidable halting status” silently replaces a restricted finite machine with an unrestricted universal model. “A million-step timeout did not catch P, so P loops” silently replaces finite observation with an infinite conclusion. “I can check a route quickly, so P differs from NP” silently promotes one verification example to a class separation. Write the missing quantifier beside each error.

Proof rehearsal before the capstone

Task A. Restate the contradiction without phrases like “it confuses itself.” Let H(P,x) be a total correct YES/NO halting checker, and define D(y) to loop if H(y,y) says YES and halt if it says NO. Test D(D). The two branches cannot be collapsed into a vague appeal to paradox: say exactly which promised answer becomes false in each branch.

Rehearsal solution

If H(D,D)=YES, D follows its loop branch, so the claim that D(D) halts is false. If H(D,D)=NO, D follows its halt branch, so the claim that D(D) does not halt is false. H must return one answer because it is total. Both violate correctness, hence no such H exists. The argument assumes D's finite description is a legal input to H and that D can implement the branch and loop.

Task B. Give a formal reason every P language is in NP, then explain why the converse is unsettled.

Rehearsal solution

For a polynomial-time decider A, set V(x,c)=A(x) and use c=ε. The verifier runs in polynomial time and accepts some certificate exactly for A's YES instances; no certificate can turn a NO into YES. This proves P⊆NP. It gives no algorithm for an arbitrary NP verifier's existential certificate search, so it does not prove NP⊆P. Nor does the failure to find such an algorithm prove that inclusion false.

Write the public explanation, then audit its scope

Write about 400–600 words for an interested reader who knows what a program is but not diagonalization. State the universal checker H's input, output and totality promise. Construct D with both branches. Apply it to its own encoded description and show the contradiction in each case. Then answer two definition checks: (1) Why does a three-option HALTS/LOOPS/UNKNOWN analyzer not violate the theorem? (2) Why does the theorem not settle P versus NP? Include the definition of P and the certificate-verifier definition of NP, prove P⊆NP, and label P=?NP open. Your final paragraph should name the formal-model assumption and avoid claiming that no individual program's termination can be proved.

Hint for structuring the explanation

Use five short paragraphs: contract, constructed program, two cases, theorem's scope, and complexity distinction. The theorem concerns a total all-case yes/no decider. The P/NP question concerns polynomial time for decision languages.

Model solution

Assume a universal program model in which programs have finite encodings and can receive encoded programs as data. Suppose a total algorithm H(P,x) always returns YES exactly when P halts on input x, and NO otherwise. “Total” means H itself finishes with one of those answers for every encoded pair.

Using H, define a program D(y). It runs H(y,y). If H answers YES, D deliberately loops forever. If H answers NO, D immediately halts. D is a finite program in the assumed model: it calls H once, branches on one bit, and either stops or repeats a fixed instruction.

Now use D's own description as its input. If H(D,D)=YES, it claims D(D) halts, but D takes the endless-loop branch and does not halt. If H(D,D)=NO, it claims D(D) does not halt, but D takes the immediate-halt branch. Either answer contradicts H's correctness. Since H had to answer, no such total correct universal halting checker exists.

This proof rules out a checker for all program-input pairs. It does not prevent proving that a particular decreasing-counter loop halts, and it does not forbid a sound analyzer that sometimes returns UNKNOWN. That analyzer has three outcomes and does not promise a definite yes/no decision on every pair. The self-input step relies on finite program encodings and universal interpretation; the proof is a mathematical theorem in that model, not an empirical test of a million runs. The Church–Turing thesis, relating informal effective computation to formal models, is separate from this contradiction.

P is the set of decision languages with deterministic polynomial-time deciders. NP is the set whose YES instances have polynomial-length certificates accepted by a deterministic polynomial-time verifier, with all NO instances rejected for every certificate. Every P language lies in NP: its verifier ignores a certificate and runs the P decider, using the empty certificate for YES inputs. This proves P⊆NP. Whether NP⊆P, equivalently P=NP, remains open. The halting theorem is about the absence of any total decider for one universal problem; it supplies neither a polynomial solver nor a superpolynomial lower bound for every NP problem.

Evidence and scoring

OutcomeEvidence to look for
Prove halting impossibilityThe construction is legal under stated assumptions and both answers are contradicted.
Distinguish P and NP definitionsDecision problems, input length, polynomial bounds and certificate quantifiers are correct.
Explain open statusP⊆NP is proved; equality is identified as open without a speculative separation claim.

Rubric, sixteen points: three for the exact H contract and model assumptions; four for defining D and applying self-input; three for both contradiction branches; two for the UNKNOWN boundary and specific-program boundary; two for correct P/NP definitions and inclusion proof; two for clear public language and an honest open-problem statement. A response that omits one branch has not completed the contradiction. A response that says NP means “not polynomial” must repair its definitions before any conclusion about P versus NP is assessed.

Keep the two limits separate

You can stop once your explanation states the machine assumptions, proves the diagonal contradiction, and accurately marks P versus NP as unresolved. The strongest result you established is an all-case impossibility theorem for the halting decider. The complexity discussion establishes P⊆NP and defines the open equality question. Further work could study reductions or formal Turing-machine encodings, but this route already has a complete, bounded proof outcome.
