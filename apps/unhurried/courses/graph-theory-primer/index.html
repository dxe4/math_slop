Sets and membership

A set records which objects belong to a collection. In roster notation, braces surround its members: A={1,3,5}. Writing 3∈A says that 3 belongs to A; writing 2∉A says that 2 does not. Repeating a member or changing the listing order leaves the set unchanged.

Worked example. Let B={3,4}. The union A∪B contains every object in either set. The intersection A∩B contains exactly the objects in both sets.

A∪B={1,3,4,5}A∩B={3}

The empty set, written ∅, has no members. A subset C⊆A has all its members in A. The subset may equal the whole set; the symbol does not require a smaller collection.

Try one. With C={1,5}, find C∩B and decide whether C⊆A.

Worked answer

C and B have no common member, so C∩B=∅. Both 1 and 5 belong to A, hence C⊆A. Empty intersection and subset inclusion ask different questions.

Watch the object. The number 3 and the set {3} are different objects. Here 3∈A and {3}⊆A are both true, but they express different relationships.

Read a network, then count what touches each place

This primer treats a graph as an exact description of connections. You will translate a small map into vertices and edge pairs, distinguish three types of route, and prove one counting fact about degrees. It is a self-contained entry route for someone comfortable with finite lists and ordinary addition. Allow about four hours including drawing, reading, the worked practice, and the capstone; the linked articles contain the main lessons.

Entry recap. A finite set lists each object once. An unordered pair {A,B} does not choose a direction. Our graphs are simple and undirected: an edge joins two different vertices, and each pair occurs at most once. A route is written as a sequence of vertices whose consecutive pairs are edges. The mathematical graph records connectivity, not the physical lengths or appearance of its drawn lines. The course ends when you can build and audit a small graph model yourself; it does not claim to teach every route algorithm or graph theorem.

Module 1: Representation

  1. Dots, lines, and what a graph forgets. Make an edge set and an adjacency list from the same small network. Check that every undirected edge appears in both endpoint lists and every isolated vertex appears in the vertex list.
  2. Three ways through a network. Use the edge list you just made to check route sequences. Label repeated edge identities separately from repeated vertices.

The bridge between these lessons is the adjacency list: it states which consecutive steps of a proposed route are legal. Once the steps are legal, route labels become questions about repetition. A pretty drawing can hide a repeated edge, especially when a route traverses it in the reverse direction. Write the edge sequence explicitly. For example, A,B,C,B uses BC twice because BC and CB are the same undirected edge. It remains a walk but fails to be a trail.

Module 2: Counting edges

  1. Every edge has two ends. Count each edge's two endpoint incidences. Use the result to check a degree report before attempting to reconstruct a graph.

Route logs already list edges, so degree counting is a natural next question: how often does each vertex appear as an endpoint among those edges? A route may visit a vertex more than its degree if it retraces streets, but the graph's degree itself depends only on the edge set. Keep route visits and incident edges distinct. The identity Σ deg(v)=2|E| works for disconnected graphs as well as connected ones, because it counts edge ends one edge at a time.

Worked mixed practice: a community-room map

Suppose rooms H,J,K,L,M have direct doors HJ, HK, JK, KL. Room M has no door in the model. First write the full adjacency list. Next classify H,J,K,H as a route. Finally, give the degrees and verify the handshaking identity. Pause to do each part before opening the solution.

Hint

Do not omit M. For the route, check consecutive pairs, then repeated edges and repeated vertices. Count endpoints of each door.

Worked solution

The adjacency list is H: J,K; J: H,K; K: H,J,L; L: K; M: none. The route H,J,K,H uses HJ, JK, KH. Each is present and none repeats, so it is a trail. It repeats H as the final vertex, so it is not a path. Degrees are H2, J2, K3, L1, M0, summing to 8. Four door edges contribute two ends each, also 8. K and L are the two odd-degree vertices, consistent with the parity consequence. M's absence from the edge list does not remove it from the graph's vertex set.

Try a deliberate model failure: if there were two different physical doors between H and J, the simple graph would still record only one pair HJ. A question about inspecting each physical door would require separate edge identities in a multigraph. The counting proof still works with the usual degree convention, but this primer's edge-set representation would no longer describe the full physical problem.

Capstone: model a local walking map

Use this explicit sample map as the assessment so your result can be checked. A garden has entrances A,B,C,D and a viewpoint E. Paths join A–B, A–C, B–C, C–D, and D–E. Give a simple graph model, a symmetric adjacency list, the degree of every vertex, and one A–E path. Explain one map fact the graph discards. Then prove the degree-sum identity for this graph by counting ends, and say why your proof method would still work if one more path were added.

Model solution

Take V={A,B,C,D,E} and E={{A,B},{A,C},{B,C},{C,D},{D,E}}. Its lists are A:B,C; B:A,C; C:A,B,D; D:C,E; E:D. Degrees are 2,2,3,2,1, summing to 10. There are five edges, each with two endpoint incidences, so 2|E|=10. One A–E path is A,C,D,E, using three legal edges and four distinct vertices. If a new path edge were added between two different entrances, each endpoint's degree would rise by one, making both sides of Σdeg=2|E| rise by two. The graph does not specify the lengths, surfaces, or positions of paths. A drawing that puts A near E would not make an A–E edge exist.

A useful stopping point

You can stop after the capstone if you can turn a stated walking map into a checkable graph, identify what its geometry no longer records, and explain why the degree sum counts every edge twice. A next route might ask whether every path edge can be traversed once; Euler trails adds connectedness and parity to answer that stronger question.
