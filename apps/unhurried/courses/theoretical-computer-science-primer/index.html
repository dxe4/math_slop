Sets and membership

A set records which objects belong to a collection. In roster notation, braces surround its members: A={1,3,5}. Writing 3∈A says that 3 belongs to A; writing 2∉A says that 2 does not. Repeating a member or changing the listing order leaves the set unchanged.

Worked example. Let B={3,4}. The union A∪B contains every object in either set. The intersection A∩B contains exactly the objects in both sets.

A∪B={1,3,4,5}A∩B={3}

The empty set, written ∅, has no members. A subset C⊆A has all its members in A. The subset may equal the whole set; the symbol does not require a smaller collection.

Try one. With C={1,5}, find C∩B and decide whether C⊆A.

Worked answer

C and B have no common member, so C∩B=∅. Both 1 and 5 belong to A, hence C⊆A. Empty intersection and subset inclusion ask different questions.

Watch the object. The number 3 and the set {3} are different objects. Here 3∈A and {3}⊆A are both true, but they express different relationships.

Make instructions and memory precise

This route asks three modest but useful questions. What must an algorithm promise? How does the number of operations change when the input grows? What can a machine remember with only finitely many states? You will end by designing a two-state reminder that recognizes a pattern in binary input. The goal is to connect a procedure, a count, and a proof of what a tiny machine does. Plan about seven hours including lesson reading, traces, revisions and the capstone; the three articles are shorter than that active study time.

Entry recap. A finite list has a length and numbered positions. An input is one such list or string; an output is the answer a procedure promises. An invariant describes something true before and after each step. A binary string is a finite row of 0s and 1s; ε denotes the empty row. You need only arithmetic, finite sets and comfort following instructions. A machine state is simply a label for the information retained so far. No programming experience is required.

A satisfying stopping point is a transition table you can run by hand and justify for every finite input, along with a clear description of what the machine does not remember. This course does not try to teach all algorithms, automata theory or complexity classes. Its exercises are small enough to check without software.

Read in three connected steps

  1. Module 1, A precise recipe: What counts as an algorithm? gives an input/output contract and a loop invariant. Follow it with When input size changes the story, which counts operations for three simple procedures. The bridge is that correctness and cost answer different questions: an algorithm can always finish correctly yet use too much work for a large input. After both lessons, write a one-sentence contract for a scan and state its exact comparison count.
  2. Module 2, Tiny memory: A machine with finite memory replaces an index and output list with a fixed transition table. It proves an invariant about parity. The bridge is the same proof discipline: identify what the state means after a prefix, show it holds initially, and show each symbol preserves that meaning. Count transitions as well as accepted strings.

Read each table aloud as “current state plus next symbol gives next state.” If you are unsure of a trace, write a row for every consumed symbol, including the starting state before the first symbol. A wrong last state usually comes from silently skipping a symbol. The parity lesson's machine accepts odd numbers of 1s; the capstone below asks for a different accepted language, so copying that table will not answer the task.

Worked mixed practice: scan versus state

Consider the string 1010. First use a scan that counts how many 1s occur; then use a two-state parity automaton. For the scan, begin count=0 and inspect positions 0 through 3. The counts after each position are 1,1,2,2. The loop invariant is that count equals the number of 1s in the inspected prefix. Four symbols are inspected, so the scan takes four comparisons. The final count is 2.

For the parity machine, start at E. The successive states are O after 1, O after 0, E after 1, E after 0. It also consumes four symbols, but retains only parity, not the total count. Its final answer is “even.” The procedures answer different contracts: the scan can report 2 exactly; the automaton can only say whether the count is odd. On 1111 and 1010 it ends in E for both, although each has a different pattern. The machine's finite memory has deliberately forgotten information its task does not need.

A tempting error is to infer from four matching steps that both methods have the same power. Their cost on this input matches, but their outputs have different information. Correctness has to be judged against the stated output. For a six-symbol input both will make six inspections or transitions in this model; neither is a “fast search” merely because it has two states.

Design a reminder machine

A device reads a finite binary log. A 1 means “turn the reminder on” and a 0 means “turn it off.” It must accept exactly those logs for which the reminder is on after the final symbol. Build a two-state deterministic automaton: name the states, choose a start and accepting state, supply all four transitions, trace ε, 110, and 101, and give a proof that your table implements the instruction. Finally state how many transitions it takes on a length-n log and distinguish that count from a runtime measurement.

Hint for the construction

The newest symbol completely determines whether the reminder is on. The empty log has not turned it on.

Model solution

Use states OFF and ON. Start at OFF and accept only ON. From either state, symbol 0 goes to OFF and symbol 1 goes to ON. Thus the transition table has OFF→OFF on 0, OFF→ON on 1, ON→OFF on 0, and ON→ON on 1. The empty string leaves OFF and is rejected. Trace 110: OFF→ON→ON→OFF, so reject. Trace 101: OFF→ON→OFF→ON, so accept.

The invariant is: after any consumed prefix, the state equals the reminder setting produced by the latest symbol in that prefix, or OFF for the empty prefix. It holds at the start. The next symbol overwrites the setting to OFF or ON exactly as the table says, so induction on prefix length proves it for every finite log. Since ON is the sole accepting state, acceptance is exactly the promised final condition. There is one transition for each input symbol, hence exactly n transitions plus a final acceptance check. Actual elapsed time depends on an implementation and machine.

Rubric, ten points: two for a complete four-entry table and correct start/accepting states; three for the three traces; three for an initial-and-preservation proof; two for an exact transition count with its units. A table that happens to work on the three examples but lacks a general invariant earns no proof points. A proof with a missing transition must be repaired before treating the machine as deterministic and total.

Stop with a machine you can defend

The reminder machine is a complete outcome for this route: its specification, table, traces, proof, and operation count all agree.
