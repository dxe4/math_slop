Substitution and equations

A letter in a formula stands for a value. Substitution replaces that letter everywhere with a chosen number. Parentheses help keep a negative input together: if f(x)=x²+2x, then f(−3)=(−3)²+2(−3)=9−6=3. Squaring happens before adding.

Worked example. To solve 3x+5=20, subtract 5 from both sides and then divide both sides by 3. Applying the same operation to both sides preserves the equality; the divisor here is nonzero.

3x+5=20⇒3x=15⇒x=5

Substitute the answer back: 3×5+5=20. This checks the proposed value against the original equation. The distributive rule also lets you expand a bracket: 2(x+4)=2x+8.

Try one. Solve 2(x+4)=18 and check the result.

Worked answer

Divide both sides by 2 to obtain x+4=9. Subtract 4 to get x=5. Checking gives 2(5+4)=2×9=18, as required.

Watch the sign. The values (−3)²=9 and −3²=−9 differ: the second expression applies the minus sign after squaring 3. Keep the parentheses when substituting negative values.

An exact identity with unequal numerical behavior

For a small positive x, the square root of 1 + x is just above 1. Subtracting 1 then asks a finite-precision calculator to recover a tiny difference between nearly equal stored numbers. This is cancellation: leading digits agree and disappear. We can compute the same real number through a different formula whose intermediate subtraction is absent.

Background capsule. The square root symbol denotes the nonnegative root. For x ≥ −1, √(1+x) is real. Multiplying (a−b)(a+b) gives a²−b². “Relative error” means absolute error divided by the magnitude of the nonzero exact answer; it can become large even when absolute error looks small. We use a three-significant-decimal-digit, round-to-nearest toy format for a transparent example, and reserve actual binary-machine claims for qualitative discussion.

Calculate the same quantity twice

Worked example. Take x = 0.004, exactly representable in our toy format. The exact square root √1.004 is about 1.00199800399. In a strict three-digit calculation, 1+x first rounds from 1.004 to 1.00; its square root is 1.00. Even if the square-root function instead receives the exact 1.004, its output rounds to 1.00. The direct expression therefore stores 1.00 − 1.00 = 0. Yet the exact answer is positive, about 0.001998. A zero result here is a property of the sequence of rounded operations, not of the function.

Now calculate x/(√(1+x)+1). The rounded root is again 1.00. Its sum with 1 is 2.00, and 0.004/2.00 gives 0.00200. The exact answer is about 0.001998, so the stable result differs by about 0.000002, roughly 0.1% of the answer. The direct result has 100% relative error. Derive the repair and its boundary

1+x−1=x1+x+1

Multiply the left side by (√(1+x)+1)/(√(1+x)+1). Its numerator becomes (1+x)−1 = x. For every real x ≥ −1 the denominator is at least 1, so division is valid; at x = 0 both sides equal zero. For small positive x the denominator is near 2 and involves addition of positive quantities, which avoids the destructive subtraction. The quotient still undergoes rounding, but it retains the size of the desired result.

Why does the direct method suffer? If the computed square root differs from the exact root by an absolute amount e, then subtraction leaves desired answer plus e. As x approaches zero, the desired answer is approximately x/2, so the ratio |e|/(x/2) can be large. This explanation assumes a nonzero absolute rounding error at the root step; when the root happens to be exactly representable, that source of error disappears. It is a sensitivity analysis of the expression, not evidence that the mathematical function itself is badly conditioned. Indeed, near x = 0 the function tends smoothly to zero with slope 1/2.

The rationalized formula also has limits. If x is so tiny that its input representation underflows to zero, neither formula can reconstruct the lost input. If 1+x overflows, the square-root path can fail. Complex x needs different branch conventions. The identity remains true over its stated real domain; its numerical advantage is particularly relevant for small positive or negative x where 1+x is near 1.

Use algebra as a numerical tool

Exercise 1. Rationalize √(9+t)−3 for real t ≥ −9, and calculate its value at t = 0.006 using three-significant-decimal-digit arithmetic. Compare the direct and rationalized routes.

Hint for exercise 1

Multiply by the sum of the two terms. Round the square root before the following arithmetic.

Solution to exercise 1

The exact identity is √(9+t)−3 = t/(√(9+t)+3), because the denominator is at least 3. At t = 0.006, the strict three-digit addition first rounds 9.006 to 9.01; √9.01 still rounds to 3.00. Direct subtraction stores zero. The rationalized denominator rounds to 6.00, giving 0.006/6.00 = 0.00100. The exact value is about 0.000999833, so the latter retains useful digits.

Exercise 2. Does rationalizing prove that every output for every real x ≥ −1 is more accurate on every computer? Identify a boundary case and explain precisely what the identity does establish.

Hint for exercise 2

Separate equality of real formulas from rounding and input representation.

Solution to exercise 2

No. At x = 0 both exact formulas give zero, and a typical correctly rounded calculation of either does too; there is no strict improvement. At x = −1, direct √0−1 gives −1 exactly in many formats, while the quotient −1/(0+1) also gives −1. More generally underflowed input, overflow, and implementation details can affect either route. The proof establishes exact real-number equality for x ≥ −1. The small-x rounding analysis explains a common advantage under the stated model, not a universal ranking.

Choose an expression with useful intermediates

Equivalent algebraic formulas need not have equivalent finite-precision behavior. For small x, x/(√(1+x)+1) avoids subtracting two nearly equal numbers and usually preserves the tiny answer. When the answer itself is zero, relative error is undefined, so report absolute error or exact equality instead. Conditioning versus stability separates a problem’s inherent sensitivity from errors introduced by a particular computation.
