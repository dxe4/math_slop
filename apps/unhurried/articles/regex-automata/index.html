What must a pattern reader remember?

Suppose a message is accepted only when its last two bits are 01. A human can glance at the end, but a machine reading left to right needs to carry just enough information from its prefix to decide at the finish. A regular expression for this language is (0|1)*01: any finite binary prefix followed by 0 then 1. We will build a deterministic machine directly and prove what its states mean.

Background capsule. A binary string is a finite word over {0,1}; ε is the empty word. A suffix is a sequence at the end of a word. The notation * in this theoretical regular expression means zero or more repetitions; | means choice. This is formal-language notation, not a promise about the extra features of a particular programming language's regex engine. A DFA has a finite set of states, one transition per state and symbol, a start state, and accepting states.

Three memories

Worked example. Use states A, B, C. A means the word has no useful trailing 0 and does not end in 01. B means it ends in 0. C means it ends in 01. Start at A and accept only C. For input 0, every state moves to B because the new word ends in 0. For input 1, B moves to C because appending 1 to a trailing 0 creates 01. A and C move to A on 1: their new ending is 1, but not 01.

Trace 1101: A→A→A→B→C, so accept. Trace 010: A→B→C→B, so reject. The latter contains 01 as an internal substring, but does not end in it. That difference is the reason the machine cannot stop as soon as it reaches C.

Prove the state labels

Claim. After reading any binary prefix w, the machine is in B exactly when w ends in 0, in C exactly when it ends in 01, and in A otherwise. The three descriptions are disjoint and exhaustive. For ε, neither ending condition holds, so A is correct. Assume the descriptions are correct for a prefix. Appending 0 always yields a word ending in 0, and every table entry on 0 leads to B. Appending 1 yields an ending 01 exactly when the former word ended in 0, which is exactly state B; hence B→C and both other states go to A. Induction proves the claim for all finite words. Since C is the only accepting state, the machine accepts exactly the language described by (0|1)*01.

The proof gives one explicit correspondence between this expression and a DFA. It does not prove the full theorem that every theoretical regular expression has an equivalent finite automaton and vice versa. That theorem needs a general construction for union, concatenation and star, plus the reverse state-elimination construction. Those are outside this short lesson. Here we only need the concrete machine and its suffix invariant.

One tempting two-state design remembers whether the most recent bit is 0. That tells you what to do when a 1 arrives, but it cannot distinguish a word that has just ended in 01 from an arbitrary word ending in 1 at the final check. In the three-state machine, C records this accepting condition, while B records the precursor that could make it true after one more bit.

L={w∈{0,1}*:w ends in 01}

Read beyond the first match

1. Trace 00101 and 00100. Which ends are accepted?

Hint for question 1

Use the table symbol by symbol, especially after the first visit to C.

Full solution to question 1

For 00101, states are A→B→B→C→B→C, so it is accepted. For 00100, the final two states after 0,0 are B,B, so it is rejected. The first word ends in 01; the second ends in 00.

2. A proposed machine accepts as soon as it ever visits C. Give a string it would accept incorrectly and explain the actual final state.

Hint for question 2

Begin with 01 and add another symbol.

Full solution to question 2

String 010 visits C after its first two symbols, but its final 0 moves C→B. It ends in 10, not 01, and must be rejected. Acceptance is decided after all input is read, not on an earlier visit to an accepting state.

A pattern with a proof attached

The expression (0|1)*01 and the three-state machine define the same particular set of finite strings. The table supplies a runnable object; the suffix invariant supplies a proof of its behavior. The example does not cover all regex syntax used in software or the full equivalence theorem. To revisit the basic DFA tuple and transition discipline, see finite automata.
