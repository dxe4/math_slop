Functions and composition

A function assigns exactly one output to each allowed input. Its domain is the set of allowed inputs; its codomain is the declared set containing the outputs. Different inputs may share an output. For f(x)=x² on the real numbers, both 2 and −2 produce 4.

Worked example. Let f(x)=2x+1 and g(x)=x². The expression f(g(3)) first applies g to 3, producing 9, and then applies f to 9, producing 19. Composition writes this as (f∘g)(3).

f(g(3))=f(9)=19

For a composition to be defined, the output of the inside function must be an allowed input for the outside function. Here both functions accept every real number, so that condition holds.

Try one. Compute g(f(3)). Does changing the order preserve the result?

Worked answer

First f(3)=7, then g(7)=49. This differs from f(g(3))=19. Composition generally depends on its order; the circle symbol names the operation, rather than promising that the two orders agree.

Watch the notation. In f(3), the parentheses name the input to f. They do not mean f multiplied by 3. Read the expression from the inside out.

What does a translation preserve?

Suppose a little graph of routes describes stages of a process. We want to assign a set to each stage and a function to each road, so that a whole route acts by composing its road functions. That assignment is a concrete functor from a path category to the category Set of sets and functions.

Background capsule. In a category, arrows have typed sources and targets, each object has an identity arrow, and composition is associative. In Set, objects are sets, arrows are functions, identities leave each element fixed, and composition is usual function composition. A functor F:C→D sends objects of C to objects of D and each arrow p:X→Y to an arrow F(p):F(X)→F(Y). The source and target must be respected before any composition law can even be written.

Assign data to three stages

Worked example. Take the path category of A→B→C, with edges a:A→B and b:B→C, its length-two path ba=b∘a, and three empty paths. Set F(A)={0,1}, F(B)={u,v}, F(C)={red,blue}. Define F(a)(0)=u, F(a)(1)=v; define F(b)(u)=red, F(b)(v)=blue. To translate the whole path, assign F(ba)(0)=red and F(ba)(1)=blue. Assign F(1A), F(1B) and F(1C) the respective identity functions.

Image arrows in Set
Source arrowImage typeOutput table
a:A→BF(A)→F(B)0↦u; 1↦v
b:B→CF(B)→F(C)u↦red; v↦blue
ba:A→CF(A)→F(C)0↦red; 1↦blue

At 0, F(b)(F(a)(0))=red=F(ba)(0). At 1, both sides give blue. The finite table establishes equality of the two functions F(A)→F(C). It also makes a tempting error visible: assigning F(ba)(1)=red would break the functor law, although every assigned arrow would still be an individually valid function.

Both functor laws matter

Exact statement and proof for this example. A covariant functor preserves identities and composition:

F(q∘p)=F(q)∘F(p),F(1X)=1F(X)

For our category, the three identities map to identities by definition. The only composition of two nonempty generating edges is b∘a, checked on both inputs above. Compositions with empty paths reduce to the identity-function laws; for example F(a∘1A)=F(a)=F(a)∘1F(A). There are no other nonempty composable pairs, since the graph stops at C. This exhausts every case and proves the specified assignment is a functor. More generally, defining images of generating edges in a free path category determines each path's image as the corresponding function composite; associativity ensures different parenthesizations agree.

Functoriality is stronger than a collection of arrows with plausible labels. If the arrow ba had been given the table (red,red), then F(b∘a)(1)=red while (F(b)∘F(a))(1)=blue. The assignment would fail. Another failure is an arrow image with wrong type, such as F(a):F(B)→F(A): it cannot be the image of a:A→B under a covariant functor. A contravariant construction reverses arrows and has a different type declaration; it is not a license to ignore typing here.

Audit a translation

1. Calculation. Keep the object and edge assignments above, but propose F(ba)(0)=blue, F(ba)(1)=red. Is the assignment a functor? Give a decisive input.

Hint for question 1

Compare F(ba) with F(b)∘F(a) at 0.

Full solution for question 1

No. At 0, the proposed F(ba) gives blue, whereas F(b)(F(a)(0))=F(b)(u)=red. Since these are functions with the same source and target and disagree at one input, the composition law fails.

2. Explanation. Could we keep every nonidentity table correct but send 1B to the constant function u on {u,v}? Explain using a composition.

Hint for question 2

Try a∘1A or 1B∘a.

Full solution for question 2

No. The identity law already demands F(1B)=idF(B), which must fix v. The proposed constant map sends v to u. Explicitly, F(1B∘a)(1)=F(a)(1)=v, but (F(1B)∘F(a))(1)=u. Thus even composition with an identity exposes the failure.

The useful test

A functor assigns typed image arrows and respects doing one thing then another. In a free path category, assign functions to generating edges and define every path image by their composite; identities and associativity then make the functor laws hold. If path images are assigned independently, check every composable pair. A finite table can certify the chosen example, but not functoriality of an unspecified construction over all sets. Next, compare two such translations through natural transformations.
