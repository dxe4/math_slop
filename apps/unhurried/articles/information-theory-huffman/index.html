Which symbols should receive short codewords?

Huffman's algorithm repeatedly joins the two least likely symbols or subtrees, building a binary tree upward. For a known finite distribution it minimizes mean binary-prefix-code length per chosen unit, a letter or predeclared block. It does not minimize every message's length or construction time.

Background capsule. In a binary prefix tree, each source symbol occupies a leaf, and its codeword length is the leaf depth. The average length is L=Σp(x)ℓ(x). Entropy is H(X)=−Σp(x)log₂p(x), with zero terms interpreted by continuity. Weights may be unnormalized positive counts because scaling every weight by the same factor leaves merge order unchanged; divide by their total for a bit-per-symbol average.

Merge a four-symbol source

Worked example. Let A, B, C, D have probabilities 1/2, 1/4, 1/8, 1/8. First join C and D to form a node of weight 1/4. Now the available weights are A:1/2, B:1/4, CD:1/4. Join B and CD to form weight 1/2. Finally join A with BCD. Assign left branch 0 and right branch 1 at each merge. One resulting code is A→0, B→10, C→110, D→111. Its average length is 7/4 bits, equal to the entropy of this dyadic distribution.

For a fair three-symbol source, each symbol has probability 1/3. Merge two 1/3 weights, then join 2/3 with the remaining 1/3. The depths are 1,2,2, giving L=5/3 bits. Entropy is log₂3≈1.585 bits, so there is a gap of about 0.082 bit. Individual prefix codewords cannot have fractional lengths; equality with entropy is not promised for a single-symbol binary code.

Change the unit before comparing the rate

Now use only letters A and B, independently drawn with the same probabilities on each draw: P(A)=3/4 and P(B)=1/4. This is an iid letter source. A one-letter binary prefix dictionary needs two nonempty words, so each has length at least one. A→0, B→1 attains one bit per letter and is optimal for that coding unit.

Instead agree in advance to split letters into nonoverlapping pairs from a known start. A pair is now one source unit. The decoder knows the dictionary, the block alignment and the exact encoded bitstream boundary. Prefix-free codewords identify successive pairs without separators. This comparison concerns complete two-letter blocks; an odd final letter and any framing or codebook metadata need a separate agreed protocol and cost calculation.

Independence gives pair probabilities P(AA)=9/16, P(AB)=3/16, P(BA)=3/16 and P(BB)=1/16. The optimization now has four leaves, rather than two. One resulting dictionary is AA→0, AB→10, BA→110, BB→111. Its expected length is (9×1+3×2+3×3+1×3)/16=27/16 bits per pair. Divide by two letters per pair to get 27/32 bits per original letter.

Predict first. Does pairing help iid fair letters? Can expected savings coexist with a longer BB codeword? Change the stipulated probabilities and inspect the exhaustive comparison; these controls do not estimate an unknown source.

The greedy claim and its limits

H(X)≤LHuffman<H(X)+1

Exact setting. The algorithm is optimal among binary prefix codes for a finite alphabet with strictly positive known probabilities, one codeword per symbol, and average weighted length as objective. A one-symbol source is a convention-sensitive edge case: with an empty codeword its optimal length and entropy are zero; if the protocol requires a nonempty word, the displayed strict upper bound fails at H=0. For at least two positive symbols, the standard bound applies. Zero-weight symbols can be removed from the source alphabet when the protocol excludes them.

Why choose the two smallest weights? In a full optimal tree, deepest leaves can be taken as siblings. Swapping a deeper high-weight leaf with a shallower low-weight leaf cannot increase weighted length, so the two lightest symbols can occupy a deepest sibling pair in some optimum. Contract that pair into one pseudo-symbol of combined weight. Every original leaf below it gains one bit, adding exactly the combined weight to total weighted length. An optimal reduced tree therefore expands to an optimal original tree, and repeating the argument gives the greedy recursion. This is the exchange and contraction proof sketch; it assumes the prefix-tree objective above, not arbitrary uniquely decodable schemes with external constraints.

The entropy bound follows from the general prefix lower bound and a comparison with Shannon lengths ⌈−log₂p(x)⌉, whose Kraft sum is at most one and whose mean is strictly below H+1 when all probabilities are positive and there are at least two symbols. Huffman does no worse than those lengths. The proof says nothing about compressing an unknown source from a handful of observed symbols without model uncertainty.

An exhaustive proof for four positive-weight leaves

For the pair weights 9,3,3,1, Huffman merges 1+3=4, then 3+4=7, then 7+9=16. The sum of the merged weights is 27: each merge adds one bit of depth to exactly its descendant leaves. Dividing by total weight 16 gives the expected 27/16 bits per pair.

We can independently prove optimality here without relying on the greedy theorem. Any prefix tree with a node having only one child can suppress that edge and shorten every affected positive-weight word. An optimal tree can therefore be full: each internal node has two children. A full four-leaf tree splits at the root into either two leaves on each side, giving depths (2,2,2,2), or one leaf and three leaves, giving depths (1,2,3,3) in some order. These are the only depth patterns.

For a fixed pattern, larger weights belong at smaller depths. If a larger weight lies deeper than a smaller one, exchanging them changes cost by the negative of their weight difference times their depth difference. Thus an exchange cannot worsen cost when putting the larger weight shallower. The balanced pattern costs 2 bits per pair. The best comb pattern costs (9×1+3×2+3×3+1×3)/16=27/16<2. This proves the proposed pair code is optimal.

The exact instrument also checks every ordered shape and label assignment: two shapes for a one-leaf/three-leaf split on the left, two with that split reversed, and one balanced shape, for five ordered shapes. Each has 24 permutations of the four distinct pair labels, making 120 cases. Some cases share the same length vector; equal probabilities do not merge the distinct labels AB and BA. The finite search corroborates the classification proof. It does not replace a general proof for arbitrarily many symbols.

The existing single-symbol code-tree lab explores the merging algorithm with its own alphabet. Setting its four weights to 9,3,3,1 gives the same weighted-length problem as this pair example, with different source labels. Dividing by two is justified here because a leaf represents two original letters; it is not a universal conversion for a four-leaf tree.

Expected length and entropy are different quantities

The original one-letter optimum of 1 bit remains correct for its two-leaf problem. The pair code improves the per-letter rate because it solves a different problem. At the worked source, letter entropy is about .811278 bits and the pair rate is .84375, so the code still lies above its entropy lower bound. The mean saving relative to the one-letter code is 1−27/32=5/32 bit per letter. BB takes three bits instead of two: expected savings do not promise savings for every realized message.

Huffman's optimality uses the actual distribution of its chosen units; those units need not be independent for the one-unit weighted-length comparison. Here iid letters justify multiplying their probabilities to obtain the pair distribution. If letters are dependent, their marginals alone do not determine that distribution. Question 4 keeps the same marginals while changing the answer.

Optional: what increasing block size guarantees under iid letters

For a fixed block length b, let Lb be the optimal expected prefix length per block. Assume a finite letter alphabet with at least two positive probabilities, iid letters, a known dictionary and fixed block framing. Each block probability is a product of its letter probabilities. Its negative logarithm is the sum of the letters' negative logarithms. Taking expectations gives H(block)=bH(letter).

Apply the standard prefix entropy bound to the block alphabet, then divide by b:

H(X)≤Lbb<H(X)+1b

The strict upper inequality follows from the Shannon-length comparison above; the alphabet assumptions exclude the convention-sensitive single-positive-symbol case. Thus optimal expected rates can approach letter entropy as block size grows. This does not say every successive block size must improve the rate or that a particular finite message gets shorter. For dependent letters, the general block bound uses their actual joint block entropy; the identity H(block)=bH(letter) need not hold. Allow about 15 additional minutes for this optional argument.

Build and assess a tree

Exercise 1. For weights 2,3,5,10, build a Huffman merge sequence and give one set of codeword lengths. Calculate average length using probabilities obtained by dividing by 20.

Hint for exercise 1

Join 2 and 3 first. Track how many joins each original weight passes through.

Full solution to exercise 1

Join 2+3=5, then join that 5 with the original 5 to make 10, then join the two 10s. The weight-10 symbol has depth 1, original weight 5 has depth 2, and weights 2 and 3 have depth 3. Weighted length is (10·1+5·2+3·3+2·3)/20=35/20=1.75 bits per symbol. One code is 10→0, 5→10, 3→110, 2→111.

Exercise 2. Three symbols are equally likely. Could a binary prefix code give every symbol a one-bit word? What does Huffman's expected length show about entropy as an achieved code length?

Hint for exercise 2

A binary root has only two one-bit branches.

Full solution to exercise 2

Three one-bit words cannot fit: their Kraft sum would be 3/2>1. Huffman uses lengths 1,2,2 and has average 5/3 bits. Entropy is log₂3≈1.585 bits, which is lower but not the achieved one-symbol mean. Longer block codes can approach entropy per symbol under the iid and framing assumptions above; that is a different coding setup.

Change the distribution, dependence and protocol

3. Fresh iid source. Let independent letters have probabilities P(A)=4/5 and P(B)=1/5. Derive the pair weights, an optimal prefix dictionary and the expected rate per pair and per original letter. Compare the two possible depth patterns.

Hint for exercise 3

The integer pair weights sum to 25. Merge the smallest two weights, or assign the largest weights to the shallowest depths of a comb.

Full solution to exercise 3

The weights for AA,AB,BA,BB are 16,4,4,1 over 25. Merges are 1+4=5,4+5=9,16+9=25. The comb dictionary 0,10,110,111 has mean (16+8+12+3)/25=39/25 bits per pair, or 39/50=.78 bits per letter. A balanced tree costs 2 bits per pair, so the comb is optimal by the four-leaf classification. The one-letter optimum is still 1 bit per letter.

4. Same marginals, dependent letters. A known source independently chooses each aligned block as AA with probability 3/4 or BB with probability 1/4. Every letter position still has marginal probabilities 3/4 and 1/4. What is the optimal pair dictionary and per-letter rate? Does it violate the entropy lower bound? Explain exactly which strings this dictionary can represent.

Hint for exercise 4

The actual block alphabet contains two positive-probability symbols, not four. Compute the block entropy before dividing by two.

Full solution to exercise 4

The known block law is (3/4,0,0,1/4), not the iid product law (9,3,3,1)/16. The dictionary AA→0, BB→1 is prefix-free and optimal, at 1 bit per pair or 1/2 bit per original letter. Block entropy is H(3/4,1/4)≈.811278 bits per pair, so the lower bound per letter is about .405639, below the achieved .5. The iid identity that would give twice the one-letter entropy is inapplicable.

With known block alignment, concatenations of these codewords represent sequences of AA and BB blocks. The dictionary has no codeword for AB or BA. Their zero probabilities justify excluding them only because this source model is known; it is not a lossless dictionary for arbitrary A/B strings. An encoder that must accept out-of-model blocks needs an agreed fallback or a different dictionary, whose costs must be included.

5. Finite-file audit. Return to the iid 3/4 source. The receiver already knows the dictionary and that the source file contains three letters. Agree to code the first pair with the worked pair dictionary, then code the last letter by A→0, B→1. Find the expected payload length. Which costs and assumptions prevent identifying 27/32 with the exact rate of every finite file?

Hint for exercise 5

There is one complete pair and one leftover letter. The receiver's known original letter count identifies when to switch dictionaries.

Full solution to exercise 5

The expected payload is 27/16+1=43/16 bits for three letters, or 43/48 bits per letter. A realized payload still has an integer length and may be longer or shorter than its mean. Knowing the original count and both dictionaries makes the final-letter switch unambiguous. If those facts must be transmitted, their framing, length and codebook overhead also count. Alternatively padding requires an agreed way to recover the original length and a new calculation for the padded final block. The ideal 27/32 rate describes complete iid pairs, not all finite-file protocols or every individual message.

Keep the optimization target visible

Huffman merging is a precise algorithm for minimizing weighted leaf depth among finite binary prefix trees with known positive weights. Ties may yield different trees with the same optimum expected length. The bounds compare that optimum with entropy, and the fair three-symbol example shows why a strict gap can remain. A source with correlations across symbols may benefit from coding blocks or a different model; a code optimized for the wrong weights need not be optimal for the actual source.

To check mastery, build a tree and then compute the weighted mean from its leaf depths rather than just reporting the merge list. The MIT discrete applied mathematics Huffman notes support the greedy method and the source-coding bounds. Our numeric weights, codewords, and exercises are original finite examples.
