Functions and composition

A function assigns exactly one output to each allowed input. Its domain is the set of allowed inputs; its codomain is the declared set containing the outputs. Different inputs may share an output. For f(x)=x² on the real numbers, both 2 and −2 produce 4.

Worked example. Let f(x)=2x+1 and g(x)=x². The expression f(g(3)) first applies g to 3, producing 9, and then applies f to 9, producing 19. Composition writes this as (f∘g)(3).

f(g(3))=f(9)=19

For a composition to be defined, the output of the inside function must be an allowed input for the outside function. Here both functions accept every real number, so that condition holds.

Try one. Compute g(f(3)). Does changing the order preserve the result?

Worked answer

First f(3)=7, then g(7)=49. This differs from f(g(3))=19. Composition generally depends on its order; the circle symbol names the operation, rather than promising that the two orders agree.

Watch the notation. In f(3), the parentheses name the input to f. They do not mean f multiplied by 3. Read the expression from the inside out.

Do two routes give the same answer?

A diagram is useful only when its arrows have actual meanings. Let A={0,1,2}, B={u,v}, C={even,odd}, and D={0,1}. We will compare two ways to turn an element of A into an element of D. The question is equality of functions, so every possible input matters.

Background capsule. A function f:A→B assigns exactly one output in B to each input in A. For f:A→B and g:B→D, the composite g∘f:A→D sends a to g(f(a)); the rightmost function acts first. Functions are equal when they have the same domain and codomain and give the same output for every input. If a codomain is changed, even an identical value table may describe an arrow of another type.

A square with complete tables

Worked example. Define f:A→B by f(0)=u, f(1)=v, f(2)=u. Define g:B→D by g(u)=0 and g(v)=1. Along the other route, define h:A→C by h(0)=even, h(1)=odd, h(2)=even, and k:C→D by k(even)=0, k(odd)=1. All four sides now have explicit domains and codomains. The square has A at its upper left, B upper right, C lower left and D lower right, with f and h leaving A, g from B to D, and k from C to D.

The two output columns match in all three rows. Hence the square commutes. If we change only k(odd) to 0, the a=1 row becomes 1 versus 0. That single counterexample proves the modified square does not commute. Testing only a=0 would miss the failure.

The table is the complete static check; the interactive checker, when available, lets you alter a finite function and locate a first mismatch.

The equation behind the picture

Exact statement and full finite verification. For functions f:A→B, g:B→D, h:A→C, k:C→D, the square commutes exactly when the two functions A→D agree:

g∘f=k∘h

For the given A, checking all elements suffices by the definition of function equality. At 0 both paths yield 0; at 1 both yield 1; at 2 both yield 0. There are no other elements, so this is a complete proof for this finite square. The same definition works when A is infinite, but a finite sample would then not prove equality. One would need a symbolic argument for an arbitrary a∈A.

The notation carries a useful type check. Both composites must start at A and finish at D. The phrase “the two paths look aligned” is not mathematical evidence if the arrows have not been defined. Nor is equality of intermediate values required: one route passes through u or v, the other through even or odd, which live in different sets. Only final outputs in D are compared. Equality is about the whole action, not the names or shape of the middle objects.

Commuting squares become especially powerful when the vertices stand for algebraic structures and the arrows preserve structure. For now, the finite function version makes the content visible and checkable. It will be the local test for a functor and for naturality later.

Decide by values

1. Calculation. Keep f,g,h above and replace k by k′ with k′(even)=0 and k′(odd)=0. Give both composite tables and decide whether the square commutes.

Hint for question 1

Only the row whose h-value is odd changes.

Full solution for question 1

g∘f has values (0,1,0) on inputs (0,1,2). k′∘h has values (0,0,0). The values differ at input 1, so the functions A→D are unequal and the new square does not commute.

2. Explanation. A learner sees matching outputs at 0 and 2 and declares the original square commutative. Explain what is missing, then state why the table above completes the argument.

Hint for question 2

Recall the quantifier in function equality.

Full solution for question 2

Equality requires agreement for every a∈A. Checking 0 and 2 leaves a=1 untested; a mismatch there is possible. The displayed table explicitly includes 0, 1 and 2, which exhaust A, and both composites share type A→D. It therefore establishes equality of the functions, not merely agreement on a sample.

A diagram is a claim to check

To verify a finite square, write each arrow's domain, codomain and table, then compare the resulting composites on every source element. One mismatch refutes commutativity. The method does not extend from finitely many tests to an infinite domain without an argument for an arbitrary input. A functor will preserve these compositional equalities when it translates one category into another.
