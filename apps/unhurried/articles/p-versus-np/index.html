Checking a proposed answer

Imagine a puzzle asking whether a set of stops admits a route under a distance limit. A proposed route may be easy to check, while finding one seems harder. That intuition motivates a formal question, but intuition alone cannot prove a gap. Complexity theory makes “easy” mean polynomial time in the length of a finite input, and “check” mean a deterministic algorithm verifies a short certificate. P versus NP asks whether every such efficiently checkable decision problem is also efficiently solvable.

Background capsule. A decision problem has a YES or NO answer for each encoded input string x. Input size is the bit length |x|, not a hidden numeric parameter that might require many bits to write. A polynomial bound is at most C|x|k for fixed constants C, k at sufficiently large sizes. A certificate c is a finite string supplied with a YES instance. The verifier must check it in polynomial time and certificates must have polynomially bounded length.

A concrete certificate

Worked example. For a finite undirected graph and two specified vertices, the decision question “is there a path with at most three edges?” has a short certificate: a list of up to four vertices from start to finish. A verifier checks that the listed endpoints are correct, each consecutive pair is an edge, and at most three edges are used. This shows how a witness can be checked. It does not show that the problem is hard to solve; in fact breadth-first search can decide this particular question efficiently without being handed a path.

The route example illustrates the difference between a witness and a solver without proving those tasks require different complexity. For a YES instance, a valid witness must exist. For a NO instance, the verifier must reject every alleged witness within the allowed length. A verifier that accepts a false route is not correct, even if most sample routes are checked accurately.

Definitions, inclusion, and an open boundary

Definitions. P is the class of decision problems solvable by a deterministic algorithm in polynomial time. NP is the class of decision problems for which a deterministic polynomial-time verifier V(x,c) and a polynomial bound on |c| exist such that x is a YES instance exactly when some certificate c makes V accept. Equivalent nondeterministic-machine language is common, but the certificate definition is enough here. NP does not mean “not polynomial.”

Theorem. P⊆NP. If a problem has a deterministic polynomial-time solver A, define V(x,c) to ignore c and run A(x). Choose the empty string as the certificate for every YES instance. For a NO instance, A rejects, so no certificate can make V accept. The verifier's runtime is A's polynomial runtime plus negligible certificate handling, and the empty certificate has length zero. This proves the inclusion from the definitions. The proof does not require finding a nontrivial witness.

Whether P=NP is open. The inclusion just proved does not tell us if it is strict. Many important problems are known to be NP-complete: if any one of them has a polynomial-time algorithm, every problem in NP does. Establishing that statement for a named problem requires explicit reductions and completeness proofs; none is supplied here, so no hardness conclusion is drawn from the route example. Also, a worst-case polynomial bound does not promise that a practical implementation is fast, and an exponential worst case does not say every input is difficult.

A common invalid argument is “I cannot see a fast way to solve this puzzle, therefore it is outside P.” Failure to find an algorithm is not a lower-bound proof. Another is “I verified one candidate quickly, therefore the problem is in NP.” Membership requires one polynomial verifier and polynomial certificate bound that work for every encoded input, with correctness in both YES and NO cases. The proof of P⊆NP meets that standard by construction.

P⊆NP;P=?NP

Use the definitions exactly

1. Suppose A decides a problem in at most 5|x|3+2 steps. Construct the certificate verifier used in the inclusion proof and state its bound.

Hint for question 1

The verifier need not use a certificate if it can already decide the answer.

Full solution to question 1

Let V(x,c) run A(x) and return its YES or NO answer, ignoring c. Use ε as the certificate for each YES input. Its length is zero. Apart from fixed overhead, V takes at most 5|x|3+2 steps, a polynomial bound. For NO inputs A rejects for every c, as required.

2. Someone says NP means “not polynomial,” so P and NP cannot overlap. Identify the error and use one explicit decision problem to refute it.

Hint for question 2

Recall the empty-certificate construction; choose an easy input property.

Full solution to question 2

NP means nondeterministic polynomial time or, equivalently here, polynomially verifiable YES certificates. The problem “does a binary string contain a 1?” is in P by a left-to-right scan of at most |x| bits. By the inclusion proof it is also in NP, using the empty certificate and the scan as verifier. Thus P and NP overlap; indeed P⊆NP.

What remains unsettled

Formal definitions make the easy inclusion P⊆NP provable. They do not settle whether the two classes coincide. A quickly checked example is not a proof that finding is intrinsically slower, and a timeout experiment cannot prove a lower bound. The scope here is decision problems over finite encodings with polynomial resource bounds; richer questions such as approximation, randomized algorithms, and reductions need their own lessons. The mathematical open question remains P=?NP.
