When does a step return to zero?

Imagine a rota with twelve positions, numbered 0 through 11. Start at 0 and move forward eight positions each turn, wrapping round after 11. You land on 8, then 4, then 0. Why did the tour visit only three positions? Changing the step to 5 visits all twelve before returning. The difference is predictable without drawing either route.

Here is the small amount of background we need. For a positive integer n, two integers have the same remainder modulo n when their difference is a multiple of n. We write a ≡ b (mod n). Thus 20 ≡ 8 (mod 12), because 20 − 8 = 12. The greatest common divisor, gcd(n, s), is the largest positive integer dividing both numbers. For instance gcd(12, 8) = 4. These definitions work for a step larger than the clock: a step of 20 has the same effect as a step of 8 on a twelve-position clock.

Our question is precise: with n positions, start at 0 and repeatedly add a positive integer step s. How many moves occur before the first return to 0? Count the return move itself. You can finish with this one answer; the clock is a complete little mathematical world.

The exact return rule

Claim. For positive integers n and s, the first return to 0 occurs after exactly

ngcd(n,s)

moves. A return after t moves means that the unwrapped total ts is a multiple of n. Write d = gcd(n, s), then n = dn′ and s = ds′. The new numbers n′ and s′ have no common divisor greater than 1. The return condition n divides ts becomes n′ divides ts′. Because n′ and s′ are coprime, this happens exactly when n′ divides t. The first positive such t is n′ = n/d.

The one number-theory tool in that reasoning deserves a label. Coprime divisor lemma: if a and b have gcd 1 and a divides bc, then a divides c. One way to justify it uses the Euclidean algorithm's coefficient identity: coprime a and b have integers u, v with ua + vb = 1. Multiplying by c shows that both terms on the left are multiples of a, so c is too. We use that established identity here; its derivation by repeated remainders is a separate exploration. The displayed orbit checks the twelve-position example, while this argument covers every positive n and s.

There is a useful second reading of the result. Exactly n/gcd(n, s) distinct positions are visited before returning. To see why, suppose positions after moves i and j matched, with 0 ≤ i < j before the first return. Then (j − i)s would be divisible by n, making an earlier positive return after j − i moves. That is impossible. If gcd is 1, the route visits every position. If the gcd is 4 on a twelve-position clock, it visits just three. This describes repeated addition; multiplication modulo n has a different orbit rule.

Try two short questions

1. Calculate. Start at 0 on a fifteen-position clock and move by 6. List the positions up to the first return, and predict the number of moves from the formula.

Hint for question 1

Find gcd(15, 6), then add 6 and reduce each total modulo 15.

Full solution to question 1

gcd(15, 6) = 3, so the predicted count is 15/3 = 5. The positions are 0, 6, 12, 3, 9, 0. The fifth addition returns to 0; the five earlier positions are distinct.

2. Explain. A friend says, “A step of 12 on a twelve-position clock must visit all positions because the step is large.” What actually happens, and why?

Hint for question 2

Replace the step by its remainder modulo 12, then evaluate the gcd.

Full solution to question 2

Adding 12 is the same as adding 0 modulo 12, so the very first move returns to position 0. Also gcd(12, 12) = 12 and the formula gives 12/12 = 1 move. Step size alone says nothing about coverage; coprimality with the number of positions does.

Stop at the first return

For repeated addition on an n-position clock, the length of the orbit from 0 is n/gcd(n, s). A coprime step visits every position; a shared factor shortens the tour. The small table can suggest this rule, but the divisibility argument explains why it holds beyond the lab's range. We have not proved the Euclidean algorithm's coefficient identity here, and we have made no claim about random or weighted steps. If you want one more idea later, the Euclidean algorithm makes that coprime tool concrete.
