How many successes are enough?

A pattern can be beautiful and false. Suppose a friend tries the formula n² + n + 3 and gets the primes 3 and 5 for the starting values 0 and 1. It is tempting to announce a formula that always gives primes. Before doing that, we must fix the claim’s domain and understand what a finite check can establish. Our precise claim is: “For every nonnegative integer n, n² + n + 3 is prime.” We will test it one input at a time.

Background capsule. A prime is an integer greater than 1 whose positive divisors are exactly 1 and itself. “For every” asks for all members of the stated domain, whereas “there exists” asks for at least one. A counterexample to a universal claim is one admissible input for which its asserted conclusion is false. We use elementary multiplication and divisibility; the lesson itself supplies the logic.

Keep an honest test ledger

Worked example. Evaluate the proposed expression at n = 0: it is 3, prime. At n = 1 it is 5, prime. At n = 2 it is 9 = 3·3, composite. The first two successes are accurate observations. The third row is an admissible input that contradicts the “every” claim. A computer could test a million more values, but those results would not erase the row at 2. For this claim, the smallest nonnegative counterexample is 2 because we checked the only smaller domain members, 0 and 1.

The logic of one failing input

Translate the symbols first

Here ℕ means {0, 1, 2, …}, the nonnegative integers. Some books start ℕ at 1, so always check the convention. The symbol ∀ means “for every,” ∃ means “there exists,” ∈ means “belongs to,” and ¬ means “not.” P(n) is a name for a claim about n, with a yes-or-no answer. The line below says: “The claim that every allowed input works is false if some allowed input fails.” You can use that sentence without memorising the notation.

∀n∈ℕ,P(n)is false if∃k∈ℕ:¬P(k)

Exact theorem of logic. A universal statement is false exactly when at least one value in its domain fails the predicate. In our worked claim, let P(n) mean “n² + n + 3 is prime.” The choice k = 2 lies in the domain, and P(2) is false because 9 has divisor 3. This is a complete disproof of that universal statement. It is not a proof that the formula is always composite or that other polynomial formulas fail; the result is limited to the stated claim.

Why can passing cases not do the opposite job? A list of tests has a last index. The universal claim includes inputs beyond it. Unless another argument covers them, the ledger says nothing about those inputs. Even a list of 0 through 1000 has no logical bridge to 1001 or to every later number. Testing is still valuable: it can reveal a counterexample, suggest a theorem, or catch arithmetic mistakes in a proposed proof. Its output must be described accurately.

One repair is to narrow the claim to a finite set we really checked: “For n = 0 or 1, the expression is prime.” That statement is true and the two calculations prove it by exhausting its domain. Another repair might be a new infinite statement with a valid argument, but we cannot conjure it from two rows. A counterexample changes what we are entitled to say.

Refute, then repair

Exercise 1. Test “For every positive integer n, n² + 1 is odd.” Find the smallest counterexample and justify that it is smallest.

Hint for exercise 1

Start at the first positive integer and check parity explicitly.

Full solution to exercise 1

At n = 1, n² + 1 = 2, which is even because 2 = 2·1. Since 1 is the smallest positive integer, it is automatically the smallest counterexample. No search over later inputs is needed.

Exercise 2. A claim says “Every integer n with n² = 1 equals 1.” Refute it, then state a true finite replacement and justify it.

Hint for exercise 2

Factor n² − 1 and remember negative integers.

Full solution to exercise 2

n = −1 is an admissible counterexample: (−1)² = 1 but −1 ≠ 1. The repaired statement is “An integer with n² = 1 is either −1 or 1.” Indeed (n − 1)(n + 1) = 0, and a product of two integers can be zero only if at least one factor is zero. Solving gives the two stated values; both square to 1.

Give each result its proper scope

A single valid counterexample completely refutes a universal claim. A finite run of successful checks establishes only its tested cases unless the domain itself is finite and exhausted. The smallest-counterexample label also needs a domain and verification of all earlier inputs. This is the useful stopping point. To turn a revised pattern into a theorem, map its assumptions and conclusion before choosing a proof method.
