The same question keeps returning

Computing a Fibonacci number by directly following its recurrence creates repeated calls. To find F6, both the F5 and F4 branches ask for F4 or smaller values again. Dynamic programming replaces this repeated tree of work with a table of distinct subproblems. The method needs a valid recurrence and an order that makes dependencies available.

Background capsule. Define F0=0, F1=1, and Fn=Fn−1+Fn−2 for n≥2. An array is a finite indexed store. Memoization stores answers after a recursive calculation; bottom-up tabulation fills answers in dependency order. Both reuse results, but their control flow differs. We count additions in an ideal arithmetic model, not bit-level time for very large integers.

Fill a small table once

Worked example. To compute F6, write entries for indices 0 through 6. Begin [0,1]. The next entries are 1,2,3,5,8, each the sum of the previous two. The complete row is [0,1,1,2,3,5,8]. Exactly five additions were made, one for each index from 2 to 6. You can also retain only the last two values if the final answer is all you need.

A memoized recursive version begins with the same base cases, checks whether an answer is already stored, and otherwise computes and saves it. On this input it may visit indices in a different order, but each distinct Fi is calculated at most once. The dependency structure is a directed acyclic graph: arrows from Fi to Fi−1 and Fi−2 point to smaller indices, so cycles cannot arise.

Correctness and cost

Claim. The bottom-up table computes the defined Fn for each integer n≥0 using max(0,n−1) additions. For n=0 or 1, return the stated base value with no addition. For larger n, initialize the first two cells correctly. Assume cells 0 through i−1 match the recurrence values. The assignment table[i]=table[i−1]+table[i−2] uses previously correct cells, so cell i is correct. Induction covers every filled cell, and the loop runs exactly once for each index 2,…,n. There are n−1 such indices, proving the addition count.

The same reasoning shows termination: the loop index increases until it passes n, and the input is finite. Storing the whole table uses n+1 cells, while a rolling pair uses constant many cells. Neither “linear time” statement counts the increasing number of bits in large Fibonacci values. If additions of large integers are charged according to bit length, the bit-operation cost is greater; the unit-addition model should be named when quoting O(n).

Memoization is useful only when subproblems recur. If every recursive call has unique inputs, a cache adds bookkeeping without avoiding duplicate calculation. It can also be wrong to cache by too small a key. For a recurrence whose answer depends on both position and remaining budget, caching only by position can merge different questions and return incorrect results. The key must include every part of a subproblem's state that affects its answer.

Fn=Fn−1+Fn−2

Worked example: updating a rolling pair safely

After computing F₅, a rolling store may hold the pair (F₄,F₅) = (3,5). To advance, first calculate the sum 3 + 5 = 8, then replace the pair by (5,8). The invariant is that the stored pair consists of two consecutive Fibonacci values. The recurrence proves its preservation because the new second entry is the sum of the old two, while the new first is the old second.

If we overwrite the first entry with 5 and then sum the two stored entries, we obtain 5 + 5 = 10, losing the old 3. An intermediate sum or a simultaneous assignment prevents that mistake. Constant storage is therefore a concrete implementation of the recurrence with a carefully stated state meaning. It saves cells when only the final value is wanted; it does not retain every earlier value for later lookup.

Check the table and its key

1. Compute F7 bottom-up and state the number of additions.

Hint for question 1

Extend the row for F6 by one sum.

Full solution to question 1

The row becomes [0,1,1,2,3,5,8,13]. The new entry is 8+5=13. Indices 2 through 7 each needed one addition, so the total is six, equal to 7−1.

2. A route problem asks whether a destination can be reached from position i with b remaining fuel units. Why might memoizing only by i be wrong?

Hint for question 2

Imagine arriving at the same position with zero fuel and with two units.

Full solution to question 2

The two arrivals can have different future possibilities: from the same position a next edge costing one unit is impossible with b=0 and possible with b=2. A cache entry keyed only by i would reuse one answer for both states. Use the pair (i,b) as the subproblem key.

Reuse with a precise state

Dynamic programming works here because the recurrence reduces every question to smaller indexed questions, and each indexed answer is reused. The table proof covers correctness and the unit-addition count. It does not make every recursive problem cheap: some have exponentially many distinct states, and others need a richer key. The recurrence analysis in a recursive algorithm's bill shows how to count a split where the subproblems are distinct.
