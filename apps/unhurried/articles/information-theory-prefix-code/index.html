Can a stream be decoded without separators?

A tiny message uses four symbols, but we send only zeroes and ones. If A is coded as 0 and B as 01, the start of 01 looks like A; a reader cannot decide immediately whether the first 0 is a complete symbol. A prefix-free code avoids that ambiguity by ensuring that no complete codeword begins any other codeword. It provides a clean way to concatenate symbols and decode them one at a time.

Background capsule. A binary tree branches left on 0 and right on 1. A codeword is the path from the root to a symbol's leaf; its length ℓ is its number of bits. For source weights p(x), the average length is L=Σp(x)ℓ(x). Entropy H(X) is average surprise in bits. A code's length is measured in actual bits per symbol, while entropy is an ideal lower-bound quantity under the coding assumptions.

A four-glyph note

Worked example. Use weights A:1/2, B:1/4, C:1/8, D:1/8. Assign A→0, B→10, C→110, D→111. The word 010110 encodes A, B, C: read 0 as A, then 10 as B, then 110 as C. Every codeword ends at a leaf, so the parser knows where to stop. The average length is (1/2)·1+(1/4)·2+(1/8)·3+(1/8)·3=7/4 bits per symbol. The entropy is also 7/4 bits because the probabilities are powers of two matching the lengths.

The lengths have Kraft sum 2⁻¹+2⁻²+2⁻³+2⁻³=1. By contrast, the proposed lengths (1,1,2) for three distinct symbols have sum 1/2+1/2+1/4=5/4. No binary prefix tree can realize those lengths: two one-bit codewords already occupy both root branches, leaving no branch for a third symbol.

Tree space and the Kraft condition

∑x2−ℓ(x)≤1

Exact claim. Every finite binary prefix-free code with nonempty finite codewords satisfies this inequality. Choose a depth D at least as large as every codeword length. A leaf at depth ℓ occupies 2^(D−ℓ) of the 2^D possible depth-D bit strings extending it. Prefix-free leaves occupy disjoint groups, so their counts sum to at most 2^D. Divide by 2^D to obtain the displayed inequality. The converse also holds for positive integer lengths: if their Kraft sum is at most one, some binary prefix code has those lengths. The tree-packing construction for the converse is beyond the counting proof here; the inequality alone does not make an arbitrary assignment of bit strings prefix-free.

A prefix-free code has unique immediate decoding because no leaf lies above another leaf; reading reaches exactly one symbol at a leaf, then restarts. A code can be uniquely decodable without being prefix-free, so do not reverse that claim. For a fixed distribution and a binary prefix code, the average length obeys H(X)≤L; this coding lower bound needs a separate proof. Zero-probability symbols may be omitted only if the protocol explicitly excludes them. If the protocol must encode them, they still need distinct codewords even though they add zero to the weighted average.

Test a code and a length claim

Exercise 1. Consider A→00, B→01, C→1 with source weights 1/4,1/4,1/2. Is the code prefix-free? Decode 10100 and find its expected length and Kraft sum.

Hint for exercise 1

Read from left to right until you hit one of the three complete words, then restart.

Full solution to exercise 1

Neither 00 nor 01 begins another listed word, and 1 begins neither of them, so the set is prefix-free. Parse 1|01|00 to obtain CBA. Lengths are 2,2,1, so L=(1/4)2+(1/4)2+(1/2)1=3/2 bits per symbol. Kraft sum is 1/4+1/4+1/2=1. The string could not be parsed as 10|100 because neither fragment is a codeword.

Exercise 2. A designer requests lengths 1,2,2,2 for four binary symbols. Can a prefix-free code have exactly those lengths? Calculate the obstruction and explain it as tree occupancy.

Hint for exercise 2

Compute 2⁻¹+3·2⁻² before trying to draw a tree.

Full solution to exercise 2

The Kraft sum is 1/2+3/4=5/4>1, so no such binary prefix-free code exists. A one-bit leaf uses half of all sufficiently long extensions. Three depth-two leaves would use three quarters more. Their disjoint occupied fractions would exceed the entire set of bit strings, which is impossible.

What a valid code guarantees

Prefix freedom guarantees that a concatenated stream can be parsed from left to right without separators. The Kraft sum checks whether a proposed collection of lengths can fit into a binary tree; the counting argument proves necessity for an existing code. It does not say that a valid tree is best for particular source probabilities. The next lesson chooses lengths by a greedy algorithm and states precisely when that algorithm is optimal. Our four-glyph example reaches entropy because its dyadic weights fit code lengths exactly, which is a special convenience.

Before moving on, distinguish three questions: Are the bit strings prefix-free? Are proposed lengths realizable by some prefix code? Is a realizable code optimal for the stated weights?
