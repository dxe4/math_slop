Ask about the middle

A catalogue sorted by identifier invites a faster search than reading every row. Binary search compares the target with a middle entry, then discards a half that cannot contain the target. Its speed rests entirely on the order guarantee. We will prove a precise version that returns the first position of a target, or reports absence.

Background capsule. A list is sorted in nondecreasing order when entry a[i] is at most a[j] whenever i<j. Equal values may appear. An interval [lo,hi) contains integer positions starting at lo and stopping just before hi. Its length is hi−lo. We use indices 0 through n−1, and the target can be compared with an entry.

A boundary search

Worked example. Search [2,4,4,4,9,12] for 4. Set lo=0, hi=6. At each round choose mid=floor((lo+hi)/2). If a[mid]<4, set lo=mid+1; otherwise set hi=mid. The first midpoint is 3, whose value is 4, so hi becomes 3. Midpoint 1 is also 4, so hi becomes 1. Midpoint 0 has value 2, so lo becomes 1. The interval is empty at lo=hi=1. A final equality test returns index 1.

This “lower bound” version does not stop as soon as it sees a matching middle. It keeps searching left because a duplicate could be earlier. For target 5 on the same list, the boundary becomes 4, and a[4]=9 fails the final test. An empty list yields boundary 0, and the final test must guard against reading position 0.

Invariant and cost

Claim. On a sorted finite list, this procedure returns the first target occurrence if one exists. The invariant is: every position below lo has value less than the target, and every position at or above hi has value at least the target. Initially these outside regions are empty. If the midpoint value is smaller, sortedness makes every position through mid smaller, so increasing lo preserves the invariant. Otherwise the midpoint and all later positions have value at least the target, so lowering hi preserves it. When the interval is empty, lo=hi is the first position whose value could be at least the target. The guarded equality test distinguishes presence from a larger successor.

Each nonempty round removes at least half of the candidate interval, rounding as needed. If its current length is m, the next length is at most floor(m/2). After k rounds its length is at most floor(n/2k). Hence for n>0, at most floor(log2n)+1 midpoint comparisons make it empty; one final equality comparison may be needed. This bound counts comparisons, not all machine operations. The interval length strictly decreases, proving termination separately from correctness.

Sortedness is essential. On [9,2,4] searching for 9, midpoint 1 holds 2, so the algorithm discards index 0 and reports absence. The code still terminates, but its invariant justification is false. Nor does binary search help when you must inspect an unsorted list from scratch merely to establish order.

T(n)≤⌊log2n⌋+1

Worked example: a target beyond every entry

Search [2,4,4,9] for 12. Initially [lo,hi) is [0,4). Midpoint 2 holds 4, smaller than 12, so lo becomes 3. The remaining interval [3,4) has midpoint 3 with value 9, also smaller, so lo becomes 4. We finish at the boundary 4, equal to the list length.

The equality check must first ask whether the boundary is below n. Here it is not, so the target is absent without reading a nonexistent entry. The invariant tells us every valid position lies below this boundary and has a value smaller than 12. A boundary position is allowed to be just beyond the list; it names an insertion place, not necessarily an existing element. That distinction also explains the empty-list case.

Test the boundary

1. Trace the intervals when searching [1,3,5,7,9] for 6, and state the returned answer.

Hint for question 1

Use half-open intervals and choose midpoint 2 first.

Full solution to question 1

Start [0,5). At midpoint 2, value 5 is smaller than 6, so move to [3,5). Midpoint 4 has value 9, so move to [3,4). Midpoint 3 has value 7, so move to [3,3). The boundary is 3, but entry 3 is 7, so the target is absent.

2. Why does stopping at the first equal midpoint fail to satisfy the first-occurrence specification? Use a concrete list.

Hint for question 2

Put several equal values around the initial midpoint.

Full solution to question 2

On [1,4,4,4,8], target 4, the first midpoint is 2 and equals 4, yet the first occurrence is index 1. Returning 2 satisfies a presence specification but violates the requested first-position contract. Continuing with hi=2 leads to boundary 1.

The useful promise

Binary search converts order into a proof of safe elimination. The interval invariant identifies what cannot be discarded; repeated halving supplies a logarithmic comparison bound. The failure on unsorted input shows why an algorithmic guarantee must carry its preconditions. For a formal language of growth bounds, continue to Big O; for algorithms that reuse answers rather than discard candidates, see remembering subproblems.
