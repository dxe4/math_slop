How do you calculate a huge power with a short ledger?

To find 745 modulo 13, multiplying 7 forty-four times is tedious. The exponent has binary expansion 45=32+8+4+1. Five successive squares of 7 give the powers with exponents 2,4,8,16,32, and the selected ones can be multiplied. This method is called repeated squaring, or binary exponentiation.

Local background: modulo a positive integer m, numbers with the same remainder may replace one another in sums and products. Binary digits represent an integer as a sum of distinct powers of two. For example 13=8+4+1, written 1101 in base two. The method works for any integer base a, any modulus m≥2, and any nonnegative exponent e. Negative exponents need a modular inverse, which may not exist, so they are outside this lesson.

Follow every square

Worked example. Start with 7 modulo 13. Squaring gives 7²=49 ≡ 10. Square that residue: 7⁴ ≡ 10²=100 ≡ 9. Again, 7⁸ ≡ 9²=81 ≡ 3. Then 7¹⁶ ≡ 3²=9 and 7³² ≡ 9²=3. For exponent 45=32+8+4+1, multiply the selected residues: 745 ≡ 3·3·9·7. Reduce in stages: 3·3·9=81 ≡ 3 and 3·7=21 ≡ 8 (mod 13). Thus the answer is 8.

A loop invariant for every bit

Set result=1, base=a modulo m, and remaining=e. Repeatedly inspect whether remaining is odd. If it is, replace result by result·base modulo m. Then replace base by base² modulo m and remaining by its integer half, discarding any fractional part. Stop when remaining=0. The exact invariant is result·baseremaining ≡ ae (mod m). It holds initially. If remaining=2q, no result multiplication occurs, and after squaring base and setting remaining=q the product stays result·(base²)q. If remaining=2q+1, the extra base is moved into result and the same calculation applies. At the end base0=1, so result is the required residue.

result·baseremaining≡ae(modm)

The remaining exponent falls from e to floor(e/2) each round, so a positive e reaches zero after floor(log₂ e)+1 rounds. Each round uses one modular square and, for a 1 bit, one more modular multiplication. This is a count of arithmetic operations; multiplying very large integers also has a bit-level cost, which this simple count does not measure. For e=0 the loop runs zero times and returns 1, consistent with a⁰=1 even when a is divisible by m.

Failure case. Squaring alone does not assemble an exponent such as 45, since 45 is not a power of two. Multiplying every square in the table would compute the sum 1+2+4+8+16+32=63 instead. The selected binary digits determine which powers join the result. Another common mistake is to halve an odd exponent without moving one copy of the base to result; that silently changes the target exponent.

Compute and check the invariant

1. Compute 329 modulo 11 by repeated squaring. Show the binary decomposition and chosen residues.

Hint for question 1

29=16+8+4+1. Successively square 3, reducing modulo 11 each time.

Full solution to question 1

The residues for exponents 1,2,4,8,16 are 3,9,4,5,3: indeed 9²=81 ≡ 4, 4²=16 ≡ 5, and 5²=25 ≡ 3. Select 16,8,4,1 for 29: 329 ≡ 3·5·4·3=180 ≡ 4 (mod 11), since 180=16·11+4. A direct check using Fermat is possible but not needed for the algorithm.

2. Start the loop for a=4, e=5, m=7. After processing the first odd bit, state result, base and remaining, and verify the invariant numerically.

Hint for question 2

Multiply result by the old base before squaring that base. Then floor(5/2)=2.

Full solution to question 2

Initially result=1, base=4, remaining=5. Because 5 is odd, result becomes 4. Square base: 4²=16 ≡ 2 (mod 7), and set remaining=2. The new invariant reads 4·2²=16 ≡ 2 (mod 7). The original target 4⁵ also has residue 2: 4² ≡ 2, 4⁴ ≡ 4, and 4⁵ ≡ 4·4=16 ≡ 2. Both sides agree.

Each bit pays for one doubling

Repeated squaring keeps the intended power intact while reducing the remaining exponent by roughly half. A binary ledger of squares and selected multiplications computes a modular power in a number of modular operations proportional to its exponent's bit length. This is an algorithmic correctness claim, not a cryptographic security claim. The method will keep the arithmetic manageable in a small RSA demonstration.
