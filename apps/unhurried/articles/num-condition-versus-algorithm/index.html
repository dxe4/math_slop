Rates and derivatives

An average rate compares output change with input change across an interval. An instantaneous derivative is the limit of those average rates as a nonzero input step tends to zero, when the finite limit exists. The derivative may be positive, negative or zero.

Worked example. For f(x)=x², compare the inputs a and a+h, with h nonzero. Expanding the square and cancelling gives the average rate 2a+h.

(a+h)2−a2h=2a+h

As h tends to zero from either direction, this expression tends to 2a. Therefore f′(a)=2a. At a=3, the instantaneous rate is 6. Using a finite step h=0.1 gives an average rate of 6.1, which is a different quantity.

Try one. What is the derivative at a=−2? What does its sign mean?

Worked answer

The same argument gives f′(−2)=−4. Near −2, a small positive input change decreases x². The derivative is the signed local rate, so the negative answer is appropriate.

Watch the limit. Substituting h=0 into the original quotient would divide by zero. Simplify for nonzero h first, then take the limit. A function can also have corners where the two directions give incompatible rates.

Where did the error come from?

An answer can be unreliable for two different reasons. The input may genuinely determine the answer weakly: a slight change in measured data causes a large output change. Or a chosen sequence of calculations may amplify rounding even though the exact problem is tame. The first is conditioning of a problem at a particular input; the second is stability of an algorithm. Treating them as synonyms hides which repair is possible.

Background capsule. If x and f(x) are nonzero, the relative input change is |Δx|/|x| and the relative output change is |f(x+Δx)−f(x)|/|f(x)|. The derivative f′(x) is the limit of output change divided by input change as Δx tends to zero. We use absolute values to compare magnitudes, and discuss finite perturbations separately from derivatives.

Two questions, two diagnoses

Worked example. First take f(x) = 1/(x−1) at x = 1.01. The exact answer is 100. If the measured input is 1.011 instead, the exact answer becomes about 90.909. The input changed by roughly 0.099% relative to 1.01, yet the output changed by about 9.09%. No perfectly accurate algorithm can tell whether the intended input was 1.01 or 1.011. The answer’s sensitivity is part of the problem.

Second take g(x) = √(1+x)−1 near x = 0.004, with the input accurately specified. Its exact answer changes moderately with x in absolute terms, but a three-digit direct calculation returned zero in the cancellation lesson. Rationalizing returned a useful result. Here the algorithmic expression is the main culprit. “Ill-conditioned input” would be the wrong diagnosis for this example when absolute output error is the quantity that matters.

These examples also warn against a scale-free label. The relative condition of g near zero is roughly 1, even though g(0)=0 makes relative output error undefined exactly at zero. For f near 1, both absolute and relative output sensitivity are large. State the input, output and error measures before declaring a problem well or badly conditioned.

Derive local relative sensitivity

κf(x)=xf′(x)f(x)

Assume f is differentiable at x and x ≠ 0, f(x) ≠ 0. Write f(x+Δx)−f(x) = f′(x)Δx + r(Δx), where r(Δx)/Δx tends to zero. Divide the output change by f(x), and divide the input change by x. To first order the ratio of relative changes has magnitude |xf′(x)/f(x)|. This is a local limiting factor, not a finite-error inequality. A finite guarantee needs a bound on derivatives over the full perturbation interval and assurance that no singularity is crossed.

For f(x)=1/(x−1), differentiation gives f′(x)=−1/(x−1)². Thus κ_f(x)=|x/(x−1)|; at 1.01 it is 101. This predicts that an input perturbation of about 0.1% may create about a 10% relative output perturbation. The finite example gives 9.09%; first-order prediction is close but not identical. At x=1 the function is undefined, and κ has no value there. At x=0 the displayed relative condition formula is also not the right measure, even if f(0) is defined.

Algorithmic stability asks a different question: did the computed output accurately solve a nearby input problem, or at least remain close to the exact output under justified bounds? A backward-stable result may still have a large forward error when the problem is ill-conditioned. Conversely, a well-conditioned problem can receive a poor answer from an unstable expression. The labels require an explicit computational model; the exact f above alone does not certify any implementation.

Make the diagnosis

Exercise 1. For f(x)=x² with x≠0, calculate κ_f(x). Predict the first-order relative output change when the input increases by 1%, then compute the exact change.

Hint for exercise 1

Differentiate x², then compare (1.01x)² with x².

Solution to exercise 1

f′(x)=2x, so κ_f(x)=|x·2x/x²|=2. The first-order prediction is a 2% output increase. Exactly, ((1.01x)²−x²)/x² = 1.0201−1=0.0201, or 2.01%. The extra 0.01 percentage point is the quadratic term in the finite perturbation.

Exercise 2. A program for f(x)=1/(x−1) returns 100 exactly for stored input 1.01. A laboratory later reports the physical x only within ±0.001. Is the program’s exact arithmetic enough to certify the physical answer as 100 ± 1? Give the actual endpoint range.

Hint for exercise 2

Evaluate f at 1.009 and 1.011; f decreases on this interval.

Solution to exercise 2

No. The admissible physical interval is [1.009,1.011]. Since f′ is negative there, its exact range is [1/0.011,1/0.009] ≈ [90.909,111.111]. That range extends about 9.091 below and 11.111 above 100, so ±1 is unsupported. Better arithmetic cannot remove the uncertainty in measured input.

Ask which promise you need

A condition number measures local response of an exact problem under a specified perturbation and error scale. Stability describes how faithfully an algorithm handles that problem in a finite arithmetic model. A small residual, a small backward error, and a small forward error are different promises. Near zeros or singularities, relative measures may be undefined or huge; use a meaningful absolute or finite-interval bound instead.
