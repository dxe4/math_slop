Powers and logarithms

For a positive integer n, aⁿ means a multiplied by itself n times. For example, 3⁴=3×3×3×3=81. For a nonzero base, a⁰=1 and a⁻ⁿ=1/aⁿ. A negative exponent describes a reciprocal.

Worked example. With base 3, the logarithm asks which exponent produces a positive input. Since 3⁴=81, log₃(81)=4. More generally, for a positive base b different from 1, log_b(x)=y means bʸ=x, with x positive.

34=81log3(81)=4

Multiplying powers with the same base adds their exponents: 2³×2²=2⁵. For positive inputs, this becomes the logarithm rule log₂(uv)=log₂(u)+log₂(v). It is a rule about a product.

Try one. Find log₂(1/8) and explain the negative sign.

Worked answer

Because 2⁻³=1/2³=1/8, the logarithm is −3. For a base larger than 1, inputs between 0 and 1 have negative logarithms.

Watch the operation. Logarithms do not generally turn a sum into a sum: log₂(2+2)=2, while log₂(2)+log₂(2)=2 happens to agree in this case. Using 2+4 instead gives log₂(6), which differs from 1+2=3 because 2³=8.

Many small bills add up

A divide-and-conquer procedure splits a task into two equal subtasks, solves each, then performs a linear amount of combining work. It is tempting to say “the pieces get smaller, so the whole algorithm must be linear.” That ignores how many pieces there are. A recurrence records both the number of subproblems and the work performed at the current call.

Background capsule. Let input size n be a positive power of two, so every split is exact until size one. Set T(1)=1 operation. For n≥2, suppose a call makes two size-n/2 recursive calls and does exactly n additional operations. A recurrence is an equation linking T(n) to costs at smaller inputs. Log2n is the integer k such that n=2k in this restricted setting.

Open the recursion tree

Worked example. For n=8, the root spends 8 combining operations. Its two children each handle size 4, spending 4+4=8. The four grandchildren each handle size 2, spending 2+2+2+2=8. Finally eight size-one leaves spend 1 each, another 8. Total cost is 32. Directly applying the recurrence agrees: T(2)=2·1+2=4, T(4)=2·4+4=12, and T(8)=2·12+8=32.

There are log2n internal splitting levels and one leaf level. At each level, the number of calls doubles while the size at each call halves, so the total cost remains n. Thus the tree suggests n(log2n+1). A tree picture is useful, but we can prove the formula without assuming it from a few examples.

Solve the recurrence on its domain

Claim. If T(1)=1 and T(n)=2T(n/2)+n for powers of two n≥2, then T(n)=n(log2n+1). Prove by induction on k where n=2k. At k=0, n=1 and the proposed value is 1·(0+1)=1. Assume it holds for n/2=2k−1. Then T(n)=2·[(n/2)(log2(n/2)+1)]+n=n(log2n−1+1)+n=n(log2n+1). Every step uses a smaller size and the specified base case, so the derivation is complete for powers of two.

This exact formula implies an O(n log n) upper bound for n≥2: log2n≥1, so log2n+1≤2 log2n. Choose constant 2 and threshold 2. More strongly, the exact count is at least n log2n, so the order is tight on the stated domain. We have not analyzed arbitrary n with uneven splits; floor and ceiling terms require their own treatment.

The base cost matters. If T(1)=0 while internal combine work remains n, the answer becomes n log2n. And if the procedure makes only one recursive call, the recurrence changes to T(n)=T(n/2)+n; borrowing the two-branch answer would be wrong. A recurrence must describe the actual algorithm.

T(n)=2T(n/2)+n

Worked example: separating leaf work from combining work

For size 16, the internal levels contain respectively 1, 2, 4, and 8 calls. Their individual sizes are 16, 8, 4, and 2. Multiplying within each level gives total combining costs 16, 16, 16, and 16, so internal work totals 64. The final level has sixteen size-one calls, each costing one, adding 16. Thus the complete total is 80.

This accounts for the two terms in n log₂ n + n: internal work and leaf work. There are 31 calls altogether, but multiplying that count by 16 would charge every call the root's combining cost. Conversely, charging only one call per depth would omit most calls. The right ledger records both how many calls exist at a level and what each costs. These sizes are all powers of two, so no rounding convention is needed.

Pay for each level

1. Compute T(16) from the formula and verify it using T(8)=32.

Hint for question 1

Log216=4, and the recurrence doubles the size-eight cost before adding 16.

Full solution to question 1

The formula gives 16(4+1)=80. The recurrence gives 2·32+16=80. The agreement checks the calculation for this input; the induction establishes all powers of two.

2. With S(1)=1 and S(n)=S(n/2)+n for powers of two, find S(8) and explain why the previous formula fails.

Hint for question 2

Follow one chain of sizes 8,4,2,1.

Full solution to question 2

S(8)=8+4+2+1=15. The previous formula would give 8(3+1)=32 because it counts two child calls at each split. This recurrence has only one child; its costs form a geometric sum along one path.

Keep the model attached

The recurrence expresses a precise accounting model: two equal recursive calls, linear combining work, and unit leaves. Its solution is exact for powers of two and supports a tight asymptotic claim there. Changing any of those assumptions changes the bill. Dynamic programming addresses a different source of waste: repeatedly recomputing the same subproblem.
