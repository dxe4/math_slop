Functions and composition

A function assigns exactly one output to each allowed input. Its domain is the set of allowed inputs; its codomain is the declared set containing the outputs. Different inputs may share an output. For f(x)=x² on the real numbers, both 2 and −2 produce 4.

Worked example. Let f(x)=2x+1 and g(x)=x². The expression f(g(3)) first applies g to 3, producing 9, and then applies f to 9, producing 19. Composition writes this as (f∘g)(3).

f(g(3))=f(9)=19

For a composition to be defined, the output of the inside function must be an allowed input for the outside function. Here both functions accept every real number, so that condition holds.

Try one. Compute g(f(3)). Does changing the order preserve the result?

Worked answer

First f(3)=7, then g(7)=49. This differs from f(g(3))=19. Composition generally depends on its order; the circle symbol names the operation, rather than promising that the two orders agree.

Watch the notation. In f(3), the parentheses name the input to f. They do not mean f multiplied by 3. Read the expression from the inside out.

What “eventually no faster” means

Suppose one routine costs 3n+5 operations and another costs 100n. Which grows faster? The first has fewer operations at n=1, but its expression is still linear. Big O records an eventual upper bound after allowing a fixed multiplier. It is a statement about functions over arbitrarily large inputs, not a stopwatch verdict on one size.

Background capsule. We consider nonnegative functions f and g on positive integers, with g(n)>0 from some point onward. “For all n≥n0” includes every larger integer. A constant C must be chosen once, independently of n. These quantifier details are the whole meaning of the notation.

Find witnesses, not just a trend

Worked example. For f(n)=3n+5 and g(n)=n, choose C=8 and n0=1. For every n≥1, 5≤5n, so 3n+5≤8n. That pair of numbers is a certificate for the Big O claim. A tighter option is C=4, n0=5. Neither is uniquely correct.

By contrast, the first few values of n2 and 100n can mislead: at n=10, they are 100 and 1,000, but at n=1,000 they are 1,000,000 and 100,000. A crossing point is interesting; a table of crossings alone cannot prove a statement extending to all later inputs. Here algebra does: n2≤100n exactly when n≤100 for positive n.

The quantified upper bound

Definition. f(n)=O(g(n)) means that there exist constants C>0 and n0 such that, for every integer n≥n0, 0≤f(n)≤Cg(n). The displayed formula states the same claim. This is an upper bound, not necessarily a tight description. For example, n=O(n2) by taking C=1, n0=1, but the reverse fails.

Proof of failure in the reverse direction. If n2=O(n), then some fixed C would make n2≤Cn for all sufficiently large positive n. Dividing by n gives n≤C. Choose any integer larger than both C and the alleged threshold. This contradicts the bound. The ability to choose n after C is fixed matters.

Big O does not mean “worst case” by itself. First decide which cost function is under study: worst-case comparisons, average expected comparisons under a named distribution, or something else. Then apply the same mathematical bound to that function. A finite benchmark can reveal a coding error or practical crossing point, but cannot establish the quantified claim. Also, a bound like O(n2) may be true for a linear algorithm; for a precise order of growth one would need matching upper and lower bounds.

f(n)=O(g(n))⇔∃C,n0∀n≥n0:f(n)≤Cg(n)

Worked example: trading a multiplier for a threshold

Consider f(n) = 2n + 100. To prove f(n) = O(n), one possible certificate is C = 102 and n₀ = 1, because 100 ≤ 100n whenever n ≥ 1. A smaller multiplier is possible if we wait longer: choose C = 3 and n₀ = 100. For every later input, 100 ≤ n, so 2n + 100 ≤ 3n.

Could we take C = 2 with some still larger threshold? No. The inequality 2n + 100 ≤ 2n is false for every input. Raising the threshold cannot fix it. In contrast, C = 2.5 works from n = 200 onward, since 100 ≤ 0.5n. The definition requires a positive real multiplier, not necessarily an integer, and it requires one fixed choice for the entire remaining range.

These certificates prove an upper-bound claim. None states that exactly three operations occur per input item, and a failed choice of constants does not refute Big O when another valid pair exists. To refute the claim itself, one must defeat every possible fixed pair, as the quadratic-versus-linear argument does.

Supply or defeat a certificate

1. Prove 7n2+2n+9=O(n2) for positive integers.

Hint for question 1

For n≥1, compare n and 1 with n2.

Full solution to question 1

For n≥1, 2n≤2n2 and 9≤9n2. Therefore 7n2+2n+9≤18n2. Choose C=18 and n0=1.

2. A friend claims 100n=O(1) because it runs quickly for n≤20. Refute the mathematical claim.

Hint for question 2

Suppose a fixed bound C exists and choose a larger input.

Full solution to question 2

O(1) would require 100n≤C for every integer beyond some threshold. Choose n larger than that threshold and C/100. Then 100n>C. Finite fast timings say nothing about this infinite quantifier.

Read the constants in the claim

A Big O proof provides a multiplier and a point after which the inequality always holds. It permits loose bounds and says nothing alone about actual seconds. The linear example and quadratic counterexample were proved by inequalities; no finite timing chart can replace them. With that language in hand, recurrence costs show how a divide-and-conquer algorithm can have a logarithmic number of levels but still perform n work per level.
