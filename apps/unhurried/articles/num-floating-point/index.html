When adding changes nothing

Suppose a calculator stores only three significant decimal digits. It shows 100 as 1.00 × 10² and 0.04 as 4.00 × 10⁻². Their exact sum is 100.04, but rounding that sum to three significant digits returns 100. The addition occurred; the stored result cannot distinguish it from the original number. This small model makes finite precision visible without pretending that ordinary computers store decimal digits in exactly this way.

Background capsule. In scientific notation, a nonzero number is a significand times a power of ten. Three significant digits preserve, for example, 1.23 × 10² but not every number between 123 and 124. Rounding to nearest chooses a representable neighbor; a tie needs a stated rule. Here we use ties to even, although none of the main examples is a tie. “Exact” below means the mathematical real-number operation before rounding; fl denotes the stored result.

Work the gaps between stored numbers

Worked example. Near 100, consecutive positive three-digit numbers in this toy system are 100, 101, 102, and so on. Their spacing is 1. Thus 100 + 0.04 = 100.04 rounds back to 100. Repeating the rounded addition twenty-five times still gives 100, although adding twenty-five copies of 0.04 in exact arithmetic gives 101. The repeated calculation rounds after every addition; the exact sum rounds only once. The order of operations matters.

A second experiment starts at 1.00. Here the spacing is 0.01; adding 0.004 rounds back to 1.00, whereas adding 0.006 rounds to 1.01. The same absolute increment may be visible at one scale and invisible at another. The number of significant digits, not a fixed absolute error, is the useful first description.

A precise statement about one rounded operation

fl(a+b)=acan hold even whenb≠0

The statement is existential, not a law for every pair. It follows in our toy system because any exact result strictly within half a spacing of a representable number rounds back to that number. At 100 the half-spacing is 0.5, so 0.04 vanishes when added once. At a power-of-ten boundary the neighboring spacings can differ, and ties require the rounding rule. These qualifications matter when predicting particular outputs.

In a normalized base-ten system with three significant digits and an unbounded exponent, rounding a nonzero real result to nearest gives relative error at most about 0.005: half a unit in the last place divided by the leading scale. This simple bound concerns one rounded result. Real hardware normally uses binary formats with finite exponent ranges, subnormal numbers, infinities, and exceptional values. Near underflow a uniform small relative-error promise may fail; overflow can produce no finite result at all. Even away from those boundaries, a sequence of individually small rounding errors can accumulate or cancel in complicated ways.

One helpful alternative for the toy repeated sum is to accumulate the small terms first: 25 × 0.04 = 1.00, then 100 + 1.00 = 101. This is a particular repair, not a universal rule that “small first” always wins. Reordering may affect other problems differently, and a stored 0.04 must itself be representable in the chosen format for this exact toy calculation.

Test the model

Exercise 1. With three significant decimal digits and rounding to nearest, evaluate fl(10.0 + 0.04) and fl(10.0 + 0.06). State the local spacing and explain both answers.

Hint for exercise 1

List the neighboring stored values near 10.0 before rounding either exact sum.

Solution to exercise 1

The stored values are 10.0, 10.1, 10.2, and so forth, so spacing is 0.1. Exact sums are 10.04 and 10.06. The first lies 0.04 above 10.0 and rounds to 10.0; the second lies 0.04 below 10.1 and rounds to 10.1. Neither is a tie.

Exercise 2. Someone argues that because each rounded addition loses less than 0.05 near 10, one hundred such additions must have total error less than 0.05. Give a counterexample using 10.0 and repeated 0.04.

Hint for exercise 2

Ask whether later additions start from the exact partial sum or the already rounded value.

Solution to exercise 2

Each stored step computes fl(10.0 + 0.04) = 10.0, so one hundred steps still store 10.0. The exact total is 10.0 + 100(0.04) = 14.0. The final error is 4.0, much larger than 0.05. The per-operation observation does not bound a chain by the same single-step amount; errors from repeated loss can add systematically.

What you can trust

A floating-point format represents a discrete set of values, whose spacing changes with scale; actual hardware formats have finitely many such values, while our toy model allowed unbounded exponents. A rounded operation can discard a nonzero contribution, and repeating it can make an error much larger than the error of one operation. The toy model proves those claims exactly within its own rules. It does not predict the final bits of a particular machine calculation without knowing its format, rounding mode, and evaluation order.
