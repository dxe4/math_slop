1. Names, expressions, and reusable functions

A program is a precise recipe for calculations. Start with const x = 3; const y = x*x + 1; console.log(y);. The first statement associates the name x with the number 3. The second evaluates an expression and names its result y. The last displays 10. A semicolon ends a statement, and // begins a comment extending to the end of its line. Comments explain intentions to a reader; the computer does not execute them. You can change the input and run the same recipe again.

Use const when the name will keep its assigned value and let when it will change. For example, let total = 0; total = total + 4; leaves total equal to 4. Here = means assignment: evaluate the expression on the right and store it under the name on the left. It is not an assertion of mathematical equality. The comparison total === 4 instead produces true or false. Comparisons such as x < 0 and x <= 2 help programs choose actions and stop loops.

The declaration function squarePlusOne(x) { return x*x + 1; } defines a reusable rule. Calling squarePlusOne(3) produces 10, and squarePlusOne(-2) produces 5. The parameter x is a local input name; return supplies the output and ends that function call. The compact form const squarePlusOne = x => x*x + 1; expresses the same rule. A function with braces after the arrow needs an explicit return to supply a value. Functions can also receive functions as inputs, which will let one sampler work with many mathematical rules.

Arithmetic uses +, -, *, /, and ** for powers. Write 2*x rather than 2x, and x**2 rather than x^2: the ^ symbol has a different, bitwise meaning in JavaScript. Parentheses make grouping explicit. Math.sqrt(x), Math.abs(x), Math.exp(x), and Math.log(x) compute square root, absolute value, exponential, and natural logarithm. Math.sin(x) and Math.cos(x) take radians; Math.PI supplies an approximation to π. A logarithm to base 10 is Math.log10(x). These are function calls with a case-sensitive name followed by parentheses.

Code does not automatically enforce a mathematical domain or track physical units. For real computations Math.sqrt(-1) produces NaN, meaning not a number; Math.log(0) produces -Infinity. Neither is a finite graph coordinate. Number.isFinite(y) checks whether an output is a finite number. If time is measured in seconds and position in meters, the constants in your formula must carry compatible units, and the plot label should say so. Keeping units in comments and labels is part of communicating the model.

A variable name should describe the quantity it stores, but a name does not enforce units or domain. const timeSeconds = 3 makes an interpretation clear to a reader, while the runtime still treats it as a number. A formula such as distance = speed*timeSeconds is dimensionally meaningful only if speed has matching distance-per-second units. Choose names and comments that preserve the model's assumptions, and validate inputs before using operations such as square roots or logarithms that have restricted real domains.

A pure numerical function returns an output determined by its input without changing hidden state. For example function g(t) { return 3*t*t-2; } gives g(−2)=10g(-2)=10 on every call. This mirrors a mathematical function and makes a laboratory reproducible. A function that reads a mutable global variable can return different results for the same t, which may be useful in an application but needs an explicit interpretation. The book's experiments favor explicit parameters so a plotted curve can be traced back to one stated rule.

JavaScript uses floating-point numbers for both ordinary decimals and most integers. The expression 0.1+0.2 may not compare exactly equal to 0.3 because those decimals have repeating binary representations. This is not a failure of arithmetic laws over real numbers; it is a feature of the finite stored approximations. Use exact symbolic reasoning for identities and numerical tolerances for computed values. Avoid changing a mathematical claim into an exact JavaScript equality test without considering representation.

Validation should match the mathematical task. A real square-root sampler should reject x<0x<0 rather than quietly send NaN to a chart. A reciprocal function should reject x=0x=0 even though JavaScript evaluates 1/0 as Infinity. Number.isFinite checks the resulting value but a clear error message can also name the violated domain condition. Stopping on a bad input is better than plotting a broken line whose missing segment looks like a feature of the function.

The value returned by a function is distinct from text printed by console.log. A reusable sampler needs actual numeric outputs to store pairs and compute comparisons; a function that only prints a number returns undefined. Likewise, an array of points is data, while plot(points,label) is a display action. Keeping computation and display separate lets one test results before drawing them and makes the same function usable in an error table, graph, or numerical integral.

Parentheses make precedence auditable. In 3*t*t-2, multiplication happens before subtraction; in (a+b)/2, parentheses ensure the sum is divided. The expression -x**2 has syntax and precedence traps in JavaScript, so write -(x**2) for the negative square or (-x)**2 for the square of a negative number. These produce opposite signs when x≠0x\ne0. Translating a written formula into code is a mathematical step that deserves its own check with a simple test input.

2. Arrays, loops, and a reusable sampler

An array stores an ordered collection: const values = [2, 5, 10];. Its first item is values[0], its last here is values[2], and values.length is 3. A point can itself be an array, [x, y], so a collection of graph samples is an array of pairs. With const points = []; the name points stays fixed, but points.push([x, y]) can append a pair to the array. Const does not make the contents of an array immutable.

A for loop repeats a calculation with a controlled counter. In for (let i = 0; i <= n; i += 1) { ... }, the initialization runs once, the comparison is checked before each repetition, and the increment runs afterward. If n is the positive integer 4, the body runs for i = 0, 1, 2, 3, 4: five times. This is the correct count for four subintervals including both endpoints. A loop whose counter never approaches its stopping condition may run forever, so bounds are mathematical assumptions as well as programming details.

For an interval [a,b][a,b], choose a positive integer nn and use xi=a+b−anix_i=a+\frac{b-a}{n}i for ii from 00 to nn. Computing each coordinate from its integer index avoids repeatedly adding an inexact step. Explicitly assigning x = b when i === n also preserves the requested final endpoint. Our sampler accepts finite endpoints with a<ba<b and nn from 11 to 19991999, yielding at most 2000 points. Restricting these inputs makes the function suitable for the book’s plotting interface. The laboratory evaluates the algebraically equal convex form a(1−i/n)+b(i/n)a(1-i/n)+b(i/n) at interior indices. It blends the endpoints and can avoid overflow in forming b−ab-a for some finite endpoints. Floating-point rounding can make the two formulas differ slightly, so the code explicitly uses aa and bb at the first and last indices.

The lab defines sample(f, a, b, n). It creates an empty array, evaluates f at each coordinate, checks that the coordinate and result are finite, appends the pair, and returns the array. A failed check throws an Error with a descriptive message. Stopping is preferable to drawing a believable curve through invalid values. This finite-value check still cannot establish continuity between samples. If you know there is a gap or singularity, divide the domain into separate valid pieces and plot them separately.

Calling plot(points, label) joins the supplied pairs in their given order. It displays a polygonal approximation, not the entire mathematical graph. More samples often improve a picture, but a narrow peak can lie between every tested coordinate. For f(x)=1xf(x)=\frac{1}{x}, samples on opposite sides of zero may be finite while a connecting segment crosses a location where the function is undefined. Domain analysis from Chapter 1 remains necessary. A table of coordinates exposes what was actually evaluated and helps distinguish those evaluations from connecting lines.

A sampler with nn subintervals returns n+1n+1 endpoint-inclusive points: indices 00 through nn. For sample(f,2,5,6), the step is 5−26=0.5\frac{5-2}{6}=0.5, so the inputs are 2,2.5,3,3.52,2.5,3,3.5, 4,4.5,54,4.5,5. Counting only six points would omit one endpoint or use a different step. A table of the first, middle, and last coordinates checks a loop more effectively than glancing at the plotted line.

Computing xi=a+b−anix_i=a+\frac{b-a}{n}i from the integer index limits accumulated rounding drift. If a step hh is repeatedly added, each addition rounds and the final value may miss bb. This difference is often small, but an endpoint has mathematical significance when a domain includes or excludes it. The code can explicitly set the final coordinate to bb as a further guarantee. If the function is undefined at bb, the sampler should instead use a half-open grid or stop before that endpoint.

Uniform sampling can miss a narrow feature. Let f(x)=exp⁡ ⁣(−(x−cw)2)f(x)=\exp\!\left(-\left(\frac{x-c}{w}\right)^2\right) on [0,1][0,1], with a small width ww. If cc lies between grid points and ww is much smaller than spacing 1/n1/n, every sampled value can be near zero even though f(c)=1f(c)=1. Joining the samples produces a nearly flat line that hides the true peak. Move the grid, refine it, or derive analytic information about the function. A graph is evidence about sampled coordinates, not a proof about every input.

Sampling across a discontinuity can create a false visual bridge. For f(x)=1xf(x)=\frac{1}{x} on [−1,1][-1,1], a uniform grid with an even number of subintervals hits zero and should reject the invalid point. A grid that misses zero may join a large negative value to a large positive value with a diagonal segment, suggesting a line through the vertical asymptote. A plotting routine should split curves at domain gaps or nonfinite values rather than connect across them. Mathematical domain knowledge guides visualization.

A loop should state its termination condition and its expected count. In for (let i=0;i<=n;i+=1), the <= comparison includes n, while < excludes it. If n is not a nonnegative integer, a sampler's count becomes unclear and may lead to invalid steps. Validate n before the loop. For computational calculus, an explicit grid size and interval are part of a reproducible experiment, not implementation trivia.

Sampling density and line thickness interact. Hundreds of points may still fail to show a rapid oscillation if the sampling frequency aliases it into a slower pattern. For sin⁡(100x)\sin(100x) on [0,2π][0,2\pi], evenly spaced points at unlucky phases can all lie near zero. Changing nn or shifting the grid may reveal the missed oscillation. Analytic bounds on frequency or adaptive sampling can guide an honest plot. Increasing nn blindly improves many pictures but does not guarantee every feature is captured.

3. Finite precision and meaningful error

The numbers used in these labs are JavaScript Number values, normally represented in binary floating-point arithmetic. A finite set of significant binary digits is combined with an exponent, rather like scientific notation in base two. Some numbers, such as 1/21/2, have exact finite binary representations. Decimal 1/101/10 does not, just as 1/31/3 has no finite decimal representation. Its stored value is a nearby representable number. Consequently 0.1 + 0.2 === 0.3 is false, and displaying the sum commonly gives 0.30000000000000004. For a calculation such as 0.1+0.20.1+0.2, inspect the stored result before using exact equality as a test.

Rounding occurs when storing inputs and when an arithmetic result is not representable. Number.EPSILON is the spacing from 1 to the next larger representable number, about 2.22×10−162.22\times10^{-16}. It is not a universal absolute accuracy guarantee. The spacing depends on magnitude, and a sequence of operations can amplify previous errors. Very large operations may overflow to Infinity; extremely small positive quantities may underflow to zero. The fact that a display has many digits does not show that all those digits describe the intended exact quantity. Every integer in the safe range ∣n∣≤253−1|n|\le2^{53}-1 is exactly representable as a Number, but many decimal fractions are not.

If qq is an exact target and q^\hat q an approximation, the absolute error is ∣q^−q∣\lvert\hat q-q\rvert. It has the same units as qq. For nonzero qq, the relative error is ∣q^−q∣∣q∣\frac{\lvert\hat q-q\rvert}{\lvert q\rvert}, a dimensionless fraction; multiply by 100 for percent error. An error of 0.01 meters is relatively small when measuring a 100-meter length and relatively large when measuring a 0.02-meter length. At q=0q=0 relative error is undefined, so use an absolute tolerance or a scale justified by the problem. For example, estimating 22 m by 1.981.98 m gives absolute error 0.020.02 m and relative error 1%1\%; near a zero target, a fixed relative tolerance alone can be unsuitable.

A practical comparison can require ∣q^−q∣≤atol+rtol∣q∣\lvert\hat q-q\rvert\le\mathrm{atol}+\mathrm{rtol}\lvert q\rvert, where atol\mathrm{atol} has the units of qq and rtol\mathrm{rtol} is dimensionless. This specifies what you regard as close; it does not prove the computation satisfies a mathematical error bound. If the exact target is unavailable and you compare two numerical methods, call their discrepancy a difference or an estimated error. Agreement is useful evidence, but both methods may share the same mistake or rounding effect. This reference-based test is asymmetric; if a symmetric comparison is wanted, one may scale by max⁡(∣q^∣,∣q∣)\max(|\hat q|,|q|) instead. Choose the convention for the question and report its units.

Conditioning asks how sensitive the exact mathematical answer is to small input changes. Stability asks whether a particular algorithm adds avoidable error beyond that sensitivity. Subtracting two nearly equal measured quantities is inherently sensitive to uncertainty in each measurement, even with exact arithmetic. Separately, using the naive quadratic formula for a small root introduces avoidable floating-point cancellation; an algebraically equivalent formula is more stable. Keeping these ideas separate helps diagnose whether better data or a better algorithm is needed.

Numbers can overflow or underflow. A product of very large finite values may become Infinity, while a very small positive quantity may round to zero. Number.isFinite catches overflow but not a positive value that has underflowed to zero. Scaling formulas can help: instead of multiplying several large terms before dividing, rearrange when algebra allows to keep intermediate magnitudes moderate. Always check that such rearrangement preserves domain and does not introduce a new zero divisor.

Rounding error is not the same as model error or discretization error. A finite-difference derivative has truncation error because it replaces a limit by a nonzero step, and rounding error because stored values are finite precision. A physical model may have parameter uncertainty even if both numerical errors are tiny. Reporting one error estimate as if it covered all three is misleading. State what was compared, what was held exact, and which source of uncertainty remains.

An error budget can combine several known contributions without pretending they are identical. If measured inputs have at most 0.01 unit uncertainty and a numerical method has a proved discretization error at most 0.002 output units, a sensitivity bound is needed to turn the input uncertainty into output uncertainty before adding the two. Simply writing 0.012 assumes the input and output units match and that the function does not amplify input error. For f(x)=100xf(x)=100x, a 0.01 input uncertainty can cause one output unit of variation, dwarfing the numerical method error. The derivative or another Lipschitz bound supplies the missing conversion.

A loop that adds readings has three different targets: the exact real sum of the stipulated input numbers, the rounded result of a chosen arithmetic procedure, and the sum of any unknown physical values behind those readings. A finite addition tree has a depth-dependent error bound

Let x1,…,xnx_1,\ldots,x_n be finite, exactly represented binary64 inputs, with n≥1n\ge1, and let SS be their exact real sum. Compute S^\widehat S by a binary tree that adds each input exactly once. Assume round-to-nearest with ties to even, no overflow or underflow, and that all nonzero exact intermediate addition results are in the normal floating-point range. Each addition then has the relative model fl⁡(a+b)=(a+b)(1+δ)\operatorname{fl}(a+b)=(a+b)(1+\delta) with ∣δ∣≤u=2−53|\delta|\le u=2^{-53}. Let dd be the largest number of rounded additions on a leaf-to-root path. If du<1du<1, the bound below holds. This bounds arithmetic on the stipulated inputs, excluding any uncertainty or conversion error in those inputs.

Subtract S=∑ixiS=\sum_i x_i from the expanded tree and apply the triangle inequality: ∣S^−S∣≤∑i∣xi∣∣pi−1∣≤γdW|\widehat S-S|\le\sum_i|x_i||p_i-1|\le\gamma_d W. The constants uu, γd\gamma_d and κ\kappa are dimensionless, while SS, WW and the absolute bound carry the common input units.

Recursive left-to-right summation starts from x1x_1 without rounding that assignment. For n≥2n\ge2, its first inputs pass through n−1n-1 additions, so d=n−1d=n-1. A balanced tree with n=2kn=2^k inputs has d=kd=k. Both use n−1n-1 additions: smaller depth does not mean fewer operations. For other sizes, count the actual paths in the stated tree. A five-input tree cannot have depth two, since a binary tree of depth two has at most four leaves. The theorem certifies each declared tree; it does not rank every tree's actual error on every input.

Separately suppose the true quantities satisfy ∣zi−xi∣≤ηi|z_i-x_i|\le\eta_i with ηi≥0\eta_i\ge0. Then ∣∑izi−S∣≤∑iηi|\sum_i z_i-S|\le\sum_i\eta_i. 4. Cancellation and the boundary between evidence and proof

Consider D(h)=(1+h−1)/hD(h)=(\sqrt{1+h}-1)/h for h>0h>0. When hh is small, the square root is close to 11. Subtracting these nearly equal values removes their leading matching digits; the remaining small difference may contain few trustworthy digits. Dividing by hh then magnifies its absolute error. This is called cancellation. The subtraction itself can be exactly rounded and still expose errors already present in its operands. A smaller hh therefore need not produce a better numerical answer.

Algebra gives a second expression. Multiply numerator and denominator by 1+h+1\sqrt{1+h}+1. Since (1+h−1)(1+h+1)=h(\sqrt{1+h}-1)(\sqrt{1+h}+1)=h, cancel the nonzero hh to obtain D(h)=11+h+1D(h)=\frac{1}{\sqrt{1+h}+1}. The equality holds over the real numbers for h≥−1h\ge-1 with h≠0h\ne0. The rearranged expression also has a value at h=0h=0, namely 1/21/2, while the original quotient is undefined there. Giving an extension a value does not change the original domain.

The rearranged formula avoids the troublesome subtraction for small positive hh. As hh approaches zero, its denominator approaches 2, suggesting an approach to 1/21/2. Chapter 4 will justify such limit statements precisely. In the lab we compare both computed formulas with 1/21/2. The displayed errors relative to 1/21/2 measure distance from that limiting target, combining the nonzero-hh difference with numerical effects. They are not pure roundoff errors. The difference between the two computed formulas is separately reported and signals their disagreement.

An experiment has a question, chosen inputs, observations, and a qualified conclusion. Predict before running; then vary one parameter and explain surprises. Even checking a million inputs cannot prove an identity for all real inputs. The conjugate calculation above is a proof of equality on its stated domain because each algebraic step applies to every allowed hh. Conversely, a trustworthy exact counterexample can disprove a universal claim. A strange floating-point output first calls for diagnosis: it may refute a claim about the implementation without refuting the corresponding real-number theorem.

The direct quotient D(h)=1+h−1hD(h)=\frac{\sqrt{1+h}-1}{h} is mathematically equal to 11+h+1\frac{1}{\sqrt{1+h}+1} for h≥−1h\ge-1, h≠0h\ne0. In floating-point arithmetic the two evaluation paths need not return the same stored value. When hh is tiny, 1+h1+h may round to 11, making the direct numerator zero and the direct quotient zero. The rationalized expression remains near one-half because it avoids subtracting nearby square roots. This is a striking example of exact algebra guiding a reliable numerical algorithm.

For moderate hh, the direct formula may be perfectly adequate. Numerical stability is not a statement that one formula is always bad; it concerns behavior under the intended input scale and precision. Compare both formulas over a range of hh values, including positive and allowed negative hh, and inspect the domain. Near h=−1h=-1, the rationalized denominator remains at least one, so it is well behaved. At h=0h=0, the original quotient is undefined, while the rationalized expression is defined and equals 12\frac12; it gives the continuous extension at that input.

A finite-difference derivative introduces another tradeoff. For f(x)=xf(x)=\sqrt{x} at x=1x=1, the forward difference equals D(h)D(h). As hh shrinks, its mathematical bias from the true derivative 1/21/2 decreases roughly in proportion to hh. But direct floating-point subtraction loses digits for very small hh. The total observed error can first decrease and then increase. A central difference or analytic derivative can improve the comparison, but each choice has its own domain and computation cost.

Proof and computation answer different questions. Evaluating D(h)D(h) at many steps shows a pattern and can reveal a failure of naive arithmetic. The conjugate identity proves equality of the two formulas on the stated domain. A later limit theorem proves that their common real value approaches 1/21/2 as h→0h\to0. These three claims have different evidence: sampled output, algebraic identity, and limiting argument. Keeping them separate makes the laboratory more instructive and prevents a smooth graph from being mistaken for a theorem.

If a program prints NaN or Infinity, the right response is to inspect the mathematical domain and the numerical path, not to delete the offending point silently. A nonfinite value might mean a true singularity, an invalid input, overflow, or an unstable formula. Those cases require different fixes. A chart that quietly drops values can obscure all of them. The lab should surface a descriptive error or annotate a deliberate domain gap so the reader can relate the code result to the mathematics.

A useful experimental record includes the formula, the input sequence, the numeric type, the computed values, and the expected limiting or exact value. When a surprise appears, change one factor at a time: use a rationalized formula at the same hh, or hold the formula fixed while varying hh. This controlled comparison isolates cancellation from truncation. An exploratory graph is strongest when paired with a symbolic explanation of why its trend occurs.

Vieta’s product relation says the two roots multiply to 1. This case separates mathematical conditioning from the stability of an algorithm. The small root itself is meaningful; the chosen subtraction wastes significant digits. Algebraic rearrangement, scale analysis, and invariant checks often improve a numerical computation more than simply asking for more decimal places.

The two-root product is an invariant check: if computed roots are xlargex_{\text{large}} and xsmallx_{\text{small}}, their product should be close to one in a suitable relative sense. The broader lesson is algorithmic choice. Exact formulas can be algebraically equivalent while their finite-precision evaluations differ greatly. Before trusting an answer, consider input scale, expected sign and magnitude, conservation or product relations, and the original equation's residual. A numerical experiment should report the method used, not just the final decimal. A useful final check compares scales before running code. For B=108B=10^8, the large quadratic root is on the order of 10810^8, and Vieta predicts the small one on the order of 10−810^{-8}. Scale analysis is cheap and often detects an error earlier than a detailed residual calculation. Deeper derivation · A numerical experiment can have two kinds of error

Approximation error comes from replacing a mathematical quantity by a nearby formula. Floating-point error comes from storing and operating on finite-precision numbers. For the forward difference f(x+h)−f(x)h\frac{f(x+h)-f(x)}{h}, Taylor expansion suggests truncation error typically of order hh when ff is sufficiently smooth. But when hh is tiny, the two function values nearly agree; subtracting their rounded representations loses significant digits, and division by hh magnifies the loss. Reducing hh helps one error and can worsen the other.

For f(x)=xf(x)=\sqrt{x} at x=1x=1, the forward quotient is 1+h−1h\frac{\sqrt{1+h}-1}{h}. Rationalizing gives 11+h+1\frac{1}{\sqrt{1+h}+1} for h≥−1h\ge-1 and h≠0h\ne0. These expressions are mathematically equal, yet the rationalized form avoids subtraction of nearly equal numbers. The visual investigation lets you watch the direct formula break down near machine precision. At hh so small that 1+h1+h rounds to 1, the direct quotient is exactly zero in floating-point arithmetic even though the derivative is 1/21/2.

A credible computation reports the formula, domain, step sizes, reference value or independent check, and a tolerance justified by the task. Absolute error ∣estimate−truth∣|\text{estimate}-\text{truth}| is useful near zero; relative error ∣estimate−truth∣∣truth∣\frac{|\text{estimate}-\text{truth}|}{|\text{truth}|} is undefined when the truth is zero. Output agreement at several steps is evidence, not a proof that an implementation or model is correct. When an exact answer exists, use it to calibrate the experiment before moving to unknown cases.

  11. Problem 11. Interpretation Can a uniform ten-point plot prove a function has no narrow peak?

    Hint. Think of a peak between grid points.

    Solution. No. Ten samples inspect only ten inputs, so a narrow peak can lie entirely between adjacent grid points and remain invisible.   37. Problem 37. Fluency Implement JavaScript sample(f,a,b,n), returning n+1n+1 pairs [x,f(x)] including both endpoints. Reject a nonfunction f, nonfinite a<ba<b, any n that is not an integer in 1≤n≤100001\le n\le10000, and any nonfinite coordinate or output. Set the final coordinate exactly to b.

    Hint. Loop from i=0i=0 through nn; form an interior coordinate with s=i/ns=i/n rather than b-a.

    Solution. Convex interpolation avoids overflow in b-a. For f(x)=x*x, a=0,b=1,n=2 the result is [[0,0],[0.5,0.25],[1,1]].

    function sample(f, a, b, n) {
  if (typeof f !== 'function' || !Number.isFinite(a) ||
      !Number.isFinite(b) || !(a < b) ||
      !Number.isInteger(n) || n < 1 || n > 10000) {
    throw new Error('invalid sample request');
  }
  const out = [];
  for (let i = 0; i <= n; i++) {
    const s = i / n;
    const x = i === 0 ? a : i === n ? b : (1 - s)*a + s*b;
    if (!Number.isFinite(x)) throw new Error('nonfinite coordinate');
    const y = f(x);
    if (!Number.isFinite(y)) throw new Error('nonfinite output');
    out.push([x, y]);
  }
  return out;
}

Concept checks

  1. What is the relative error if truth is zero?

    • Always zero
    • Undefined by the usual formula
    • Equal to absolute error

    Answer. Undefined by the usual formula. The usual relative error divides by the magnitude of the true value, which is zero.

  2. What happens to a loop for(let i=0;i<4;i++)?

    • It runs 3 times
    • It runs 4 times
    • It runs 5 times

    Answer. It runs 4 times. The loop body runs for i=0,1,2,3.

  3. Does a close numerical match prove an identity for every real xx?

    • Yes
    • Only with enough samples
    • No

    Answer. No. Finite samples cannot establish a universal mathematical statement.

    • [f(x+h)−f(x)]/h[f(x+h)-f(x)]/h

    • [f(x)−f(x−h)]/h[f(x)-f(x-h)]/h

    Answer. [f(x+h)−f(x−h)]/(2h)[f(x+h)-f(x-h)]/(2h). It uses samples on both sides of xx and divides by their separation 2h2h.

  5. Why may smaller hh worsen a finite-difference estimate?

    • Rounding and cancellation can dominate
    • The derivative changes definition
    • Limits stop existing

    Answer. Rounding and cancellation can dominate. Truncation may shrink, while subtractive roundoff can grow relative to hh.

Chapter synthesis

  • Functions turn mathematical rules into reusable calculations; arrays and bounded loops organize their sampled values.
  • A plotted line interpolates finitely many samples, so domains and unsampled behavior require separate reasoning.
  • Finite precision makes algebraic form matter. Absolute and relative errors answer different questions, and numerical agreement is evidence rather than proof.

Common mistakes to check

  • “A smoother plot proves the function is continuous.” Connecting finitely many samples can conceal a jump, hole, or pole; continuity requires information about every nearby input. Test with problem 35
  • “A smaller step and more printed digits always mean greater accuracy.” Cancellation can make a smaller hh less reliable, and extra displayed digits can describe a rounded computation rather than the exact target. Test with problem 23
